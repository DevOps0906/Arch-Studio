# 03 화면과 UX: Arch Studio (arch-studio)

작성일 2026-10-16. 기능 정본은 `docs/file/02-요구사항/01_PRD.md`(AR-F-001~038, 4장 요금·상태, 9장 도면 자동 생성)이고, 이 문서는 화면과 흐름으로 구체화만 한다. 테이블·RPC·Route Handler·잡·오류 코드 이름은 02·04·05장과 같은 공통 계약을 쓴다. 화면 구조 코드는 `docs/file/03-설계/디자인/DASHBOARD_PATTERNS.md`(A~O), 토큰·컴포넌트 규칙은 `docs/file/03-설계/디자인/DESIGN_SYSTEM.md`를 따른다. 사용자 노출 문구는 한국어이며 카피는 PRD 6.1절(`docs/file/02-요구사항/01_PRD.md 6.1절`)과 9.7절(`:446`) 금지 문구를 통과해야 한다. 근거 없는 수치는 "제안"이다(이유: 신규 제품이라 사용 데이터가 없다).

## 1. 정보 구조와 화면 목록

데스크톱 앱(Tauri, React Router)과 클라우드 웹(Next.js 16.2)은 화면을 나눠 맡는다. 설계 작업(모델, 판정, 도면, AI 요청)은 데스크톱과 웹 스튜디오(`app.` 서브도메인, 1.2절·ADR-001)에 있고, 마케팅 웹은 랜딩·다운로드·샘플·계정·결제를 맡는다. 결제와 OAuth는 데스크톱에서도 시스템 브라우저로 연다(`D:/WorkSpace/platform/docs/Tauri/README.md:124`, `:182`).

상태 약어(PRD 4.3절 상태, `docs/file/02-요구사항/01_PRD.md 4.3절`): 체험 = 체험 14일, 체험만료 = 체험 만료·라이선스 없음, 영구 = 영구 + 업데이트 유효, 폴백 = 영구 + 업데이트 만료, 구독 = 월 구독 활성, 구독만료 = 월 구독 만료·라이선스 없음. "열람"은 PRD의 "열람·내보내기만"이다.

화면 표의 `패턴` 열은 `docs/file/03-설계/디자인/DASHBOARD_PATTERNS.md`(구조 A~O), `시각` 열은 `D:/WorkSpace/platform/docs/products/_design-guide/DASHBOARD_VISUAL.md`(시각 V-A~V-N, 1장 분석 절차)를 따른다. 값은 제안이며 화면 착수 시 1장 7단계로 다시 확인한다(2026-10-16).

### 4.5 히어로 (정지 이미지 + CSS/SVG 연출 1회, D-37)

2026-10-29 결정 D-37: 실시간 3D(three/R3F)는 랜딩 번들 예산과 개발 비용 대비 효과가 낮아 **정지 이미지 + CSS/SVG 연출 1회**로 축소한다. `HERO_3D.md`의 기기별 3D 구성·저사양 판정·3D 성능 예산은 적용하지 않고, 정지 이미지 규칙(LCP·CLS)과 접근성 규칙만 따른다. 3D 재도입은 번들 분석과 효과 측정 뒤 `HeroVisual` 교체로 한다. 아래는 소재만 정한다.

| 항목 | 내용 |

## 8. 대시보드 셸과 좌측 GNB (2026-10-19 추가, 원본 프로젝트 메뉴 이행)

이 장은 Arch Studio 설치형 앱 창(Tauri)과 웹 스튜디오(`app.`, 1.3.1·1.3.2절)가 함께 쓰는 공통 셸(헤더 + 좌측 GNB)과 홈(`/projects`) 구성을 정한다(ADR-001 1장 ① 기능 동등, 2장 같은 `packages/features` 화면 + 셸 래퍼 2개). 이 제품의 주 앱 셸은 `/dashboard`가 아니라 이 셸이고, 1절 앱 셸 문단(:15)의 왼쪽 내비 6개(프로젝트, 법규 채팅, 법규 위키, 크레딧, 라이선스, 설정)와 프로젝트 안 상단 탭 8개가 대상이다. 마케팅·계정 웹(1.2절: 랜딩·다운로드·계정·결제)만 이 셸을 쓰지 않는다. 셸 안 차이는 어댑터 `capabilities`로만 나눈다(8.6절). 이 제품은 신규 제품이라 원본 저장소가 없고(`docs/file/01-관리/README.md:19`), 이식 원천 리뷰는 `docs/reference/reviews/FortuneDocs.md`(사주 PDF SaaS, `:7`)다. FortuneDocs의 기능 요구 5개(`docs/reference/reviews/FortuneDocs.md:31`)·비기능 2개(`:32`)·트리 누락 화면(`:49`)은 8.7절 표에서 모두 새 위치로 보낸다. 사주 도메인 화면은 신비로운AI(astro-ai)가 가져가고(`D:/WorkSpace/platform/docs/products/astro-ai/README.md:21`, `:31`), 이 제품은 "결정적 수치는 엔진이 계산하고 LLM은 서술만"이라는 원칙만 가져온다(`docs/reference/reviews/FortuneDocs.md:47`, README 3장 `:37`). 1절 화면 표의 경로·권한·상태 접근은 그대로이고, 이 장은 메뉴 묶음·순서·셸 동작만 더한다. 새 경로는 없다. 다른 제품과 `_design-guide` 공용 패턴은 바꾸지 않는다(arch-studio 전용).

디자인 시안: Design 캔버스 "Arch Studio 대시보드 · GNB 초안"(맨 위 줄: 홈 펼침·접힘 + 메뉴 화면 5개(법규 채팅, 법규 위키, 크레딧, 라이선스, 설정) + 렌더러 기본 모바일 2장, 컴포넌트 `Shell.dc.html`). 시안은 라이트(트레이싱지) 테마만 그리고(01장 D-34), 수치·프로젝트 이름·기기 이름은 모두 [예시]다. 모바일 2장은 렌더러가 자동으로 만드는 화면이며, 설치형은 창 최소 폭 1024px라(6.3절) 해당하지 않고 웹 스튜디오 ~767 구간(6.4절 웹 스튜디오 배치표)의 참고 시안으로 쓴다.

판정 패널 하단 고정 문구와 체험만료·구독만료 열람 모드는 3.5절 그대로. 열람 모드에서는 도구 레일·맥락 도구줄을 숨기고 다음 단계 버튼은 남긴다.

### 9.3 단계 전환

- 길은 6단계 막대와 다음 단계 버튼 두 가지. 같은 셸 안에서 바뀌고 페이지를 다시 그리지 않는다(URL은 단계별로 바뀌어 뒤로 가기 가능).
- 전환하면 선택은 풀고 카메라·확대 상태는 단계별로 기억한다. 판정 요약(막대·패널·상태줄)은 모든 단계에서 같은 값.
- 1 대지, 3 프로그램, 6 렌더·제안서는 이번 범위에서 기존 화면 구조를 셸 안에 넣는다(시안 없음).

### 9.4 3구간 동작

| 구간 | 배치 |
|---|---|
| 데스크톱 1200~ | 레일 · 왼쪽 목록 · 캔버스 · 오른쪽 패널 4열. 패널을 접으면 띠 폭만 남음 |
| 태블릿 768~1199 | 레일 · 캔버스 · 오른쪽 패널 3열. 왼쪽 목록은 상단 `≡` 또는 탭 줄 목록 버튼으로 여는 왼쪽 서랍. 상태줄의 엔진·규칙 팩, 상단 크레딧 숨김 |
| 모바일 ~767 | 캔버스 전면. 레일은 탭 줄 아래 가로 도구줄(끝에 속성·판정·레이어 버튼). 오른쪽 패널은 아래 시트(최대 높이 70%), 왼쪽 목록은 왼쪽 서랍(폭 85%). 단계 막대는 현재 단계만 이름, 나머지는 번호. 맥락 도구줄은 캔버스 왼쪽 아래. 판정 수는 상태줄에 항상 |

설치형 창 최소 폭(6.3절)에서는 태블릿 행을 따른다.

### 9.5 GNB 작업공간 메뉴 (8.3절 묶음 "작업공간")

현재 GNB(`packages/features/src/shell/nav.ts` `NAV_ITEMS`)에는 모델·도면이 없고 프로젝트 안 탭에만 있다. 프로젝트 다음에 묶음 "작업공간"(모델링 → `/model`, 평면 → `/plans`, 도면 → `/sheets`)을 둔다.

| 상황 | 누르면 | 메뉴 표시 |
|---|---|---|
| 프로젝트 안(열린 프로젝트) | 그 프로젝트의 해당 단계(9.3절 전환과 같음) | 현재 단계 메뉴에 현재 위치 표시(8.6절) |
| 프로젝트 밖, 최근 연 프로젝트 있음 | 최근 프로젝트(웹뷰 저장소의 마지막 프로젝트, 이 PC·보는 사람별 편의 값)의 해당 단계 | 툴팁 "<프로젝트 이름>에서 열기" |
| 최근 프로젝트를 정할 수 없음(삭제됨 등), 프로젝트 1개 이상 | 프로젝트 고르기 창: 최근 수정 5개(이름·대지 라벨·수정일. 목록 행 `ProjectSummary`에 용도지역·판정이 없음) + "모든 프로젝트 보기" → `/projects`. 고르면 그 프로젝트의 해당 단계 | 열림 |
| 프로젝트 목록을 읽지 못함 | 이동 없음 | 비활성 + 이유 "프로젝트 목록을 읽지 못했습니다" + "프로젝트 목록으로 가기"·"다시 시도" |
| 프로젝트 0개 | 이동 없음 | 비활성 + 이유 "프로젝트를 먼저 만드세요" + "새 프로젝트" 링크 |
| 평면(P1) 기능이 없는 빌드 | 이동 없음 | 비활성 + 이유 "다음 버전에서 제공합니다"(제안 문구) |
| 체험만료·구독만료 | 해당 단계를 열람 모드로(9.2절) | 열림(숨기지 않음, 1절 :37) |

로컬 기능이라 오프라인·비로그인에서도 열린다(8.6절 클라우드 메뉴 규칙 대상 아님). 비활성 이유는 메뉴 옆 글자와 `aria-disabled` + 툴팁으로 보이고 포커스는 받는다(6.1절 키보드). 최근 프로젝트 기억은 권한을 정하지 않는다(8.2절).

### 9.6 도면 주석 규칙 (3.8절 미리보기, 개발서 12장 반영 대상)

| 항목 | 규칙 |
|---|---|
| 자동 작도 | A-SITE-BNDY·A-SETBACK·A-MASS·A-DIMS 등은 편집 화면에서 잠금·회색(`--color-concrete`), 도구가 집지 못함. 형상은 고칠 수 없다(기존 원칙) |
| 사람 주석 레이어 | `A-ANNO-USER` 하나(DXF 매핑 표에 행 추가, 사무소 매핑에서 이름 변경 가능) |
| 저장 | `SheetSpec.annotations[]` 하나: 기존 `annotation_overrides`(자동 주석 옮기기·문구·숨김)를 `kind:"override"`로 흡수 + `dim`·`text`·`leader`·`cloud`. 로컬 `sheets`(모델)에 저장하며 도면 파일이 아니다 |
| 위치 | 화면 좌표가 아니라 앵커(`ref` 모델 객체 ID + `part` vertex·edge·center + `index` + `at`) + 용지 mm 오프셋(저장 전 0.1mm 반올림). 모델이 바뀌면 주석이 따라감 |
| 치수 값 | 사람이 숫자를 넣지 않는다. 엔진이 두 앵커 사이 거리를 계산해 `{값}` 틀을 채움(엔진 반올림 규칙) |
| 서체·크기·색 | DraftingProfile에서만(주석마다 두지 않음) |
| 고아 주석 | 앵커 `ref`가 모델에 없거나 `index`가 범위 밖이면 고아. 위치를 추측하지 않고 출력(DXF·PDF·SVG·PNG)에서 뺀다. 편집 화면에서만 빨간 파선(`--color-danger`) + "앵커 없음", 목록에 "주석 4 · 고아 1", 행동 [앵커 다시 고르기]·[삭제]. 내보내기 대화상자에 "고아 주석 n개는 출력에서 빠집니다"(막지 않음), 기존 `unapplied`와 같은 경로로 보고 |
| 결정성 | 출력 = `drafting(model, sheetSpec, profile)` 순수 함수. 그리기 순서는 `id` 사전순(배열 순서 무관), 앵커 좌표는 엔진 기하·mm 정수. 주석 없는 시트 출력은 지금 골든과 바이트 동일(회귀 0), 주석 포함·고아 포함 골든 추가. 상태줄 출력 지문(해시 앞자리) 표시는 선택 |
| 이행 | `annotation_overrides[i]` → `{ id: "ov-" + target, kind: "override", … }` 1:1 변환. 외부 계약(zod `packages/domain/src/sheet.ts`, 04장 4.7.3 SheetSpec, 계약 corpus `apps/api/tests/contract/corpus/sheet_spec.json`) 변경이라 위험 높음(AR-06-086) |

zod 스키마 초안(앵커·discriminatedUnion)은 `git show 06c3d55:docs/design/WORKSPACE_SPEC_DRAFT.md` 3.2절. 확정 스키마의 정본은 04장 SheetSpec(AR-06-086에서 갱신).
