## 4. 요금과 크레딧

판매 구조는 세 층이다. (1) 앱 본체는 시리얼 번호로 영구 소유한다. (2) 법규·기능 업데이트는 연간 업데이트 플랜으로 받는다. (3) 비용이 드는 AI 작업은 크레딧으로 낸다. 초기 비용이 부담인 사용자를 위해 월 구독을 함께 둔다. 사용자가 AI 비용을 직접 해결하는 방식(사용자 키)은 기본 경로로 두지 않는다. 이유: 타깃 사용자에게 API 키 발급은 진입장벽이 높고, 법규 검토는 법령 DB가 있는 서버에서만 동작하며, 서버 크레딧에 묶인 기능은 복제판에서 쓸 수 없어 영구 라이선스의 복제 위험을 줄인다. 사용자 키는 Phase 2 선택 기능으로만 검토한다(D-10).

크레딧 표준가는 1크레딧 = 100원(부가세 포함, `pack_100` 기준)이다. 사용자에게는 토큰이 아니라 작업 단위 크레딧을 보여 준다. 실행 전에 차감 크레딧을 확정해 보여 주기 위해서다(`D:/WorkSpace/platform/docs/products/nomad-docs/01_PRD.md 9.4절`와 같은 원칙). 가격은 부가세 포함 표시(D-6)다.

- 위 표의 각 행은 **상품 하나**를 가진 사용자의 권리다. 여러 상품을 가진 사용자(예: 업데이트 만료 영구 + 활성 구독)의 실제 권리는 권리별 OR·최대값 합성이며 고정 순위가 없다. 좌석 배정 상태(미배정·회수·좌석 부족)별 동작은 `ADR-001` 4.7절이 정본이다. 만료 상태의 클라우드 프로젝트는 열람·내려받기가 유지되고 보존·삭제는 `ADR-001` 3.3절(승인 2026-10-28)이다. 영구 폴백만 남은 조직은 보존 시계가 시작되지 않는다(D-H5 ①).

- AI 렌더·제안서는 업데이트 만료 상태에서도 크레딧으로 열어 둔다(제안: 원가가 크레딧으로 회수되고 사용 습관을 유지한다). 클라우드 법규 검토는 최신 법령 RAG를 쓰므로 업데이트 플랜 전용이다(D-8).

### 4.8 `core.plans.features` 키 해석 (서버만 읽는다, `docs/file/03-설계/공용코어/DB_CONVENTIONS.md:241`)

영구 라이선스는 플랜이 아니므로, 서버 함수 `arch.org_features`가 라이선스 상태와 플랜 `features`를 합쳐 최종 값을 낸다. 라이선스만 있고 업데이트가 만료된 조직은 아래 "폴백" 열을 쓴다.

| 키 | 의미 | trial | updates_yearly | sub_monthly | 폴백 | 키가 없을 때 |
|---|---|---|---|---|---|---|
| `cloud_review` | 클라우드 법규 검토 | true | true | true | false | false |
| `rule_pack_updates` | 규칙 팩·빌드 업데이트 | true | true | true | false | false |
| `ai_render` | AI 렌더·제안서(크레딧) | true | true | true | true | false |
| `local_gpu_render` | 로컬 GPU 렌더(Phase 2) | false | true | true | false | false |
| `render_max_px` | 렌더 최대 해상도 | 1024 | 4096 | 4096 | 4096 | 1024 |
| `site_lookups_per_day` | 대지 조회 일일 상한 | 10 | 30 | 30 | 30 | 10 |
| `ai_chat_turns_per_day` | 법규 채팅 일일 상한 | 20 | 200 | 200 | 0 | 20 |
| `cloud_projects_max` | 클라우드 사본 프로젝트 수 | 3 | 100 | 100 | 100 | 3 |
| `max_activations` | 사용자당 활성화 PC 수(D-H5 ③). 여러 상품·좌석이면 최대값(합산 아님) | 1(제안) | 2 | 2(D-H1, 기존 1 폐기) | 2 | 1 |
| `seats` | 판매 좌석(사용자) 수, D-H1. 판매 시작 전 스키마에 추가 | 1(제안) | 구매 수 | 구매 수 | 구매 수 | 1 |
| `web_studio` | 웹 스튜디오 편집(false면 열람·내보내기만) | true | true | true | false | false |
| `web_sessions_max` | 계정당 동시 웹 세션 | 미정 | 미정 | 미정 | 미정 | 미정 |

위 열은 상품 하나의 값이다. 사용자에게 적용되는 최종 값은 보유 상품 값의 합성(불리언 OR, 수치 최대값, `ADR-001` 4.7절)이며 `org_features`가 사용자 기준으로 낸다. `web_studio`가 폴백 false여도 활성 구독이 있으면 true가 된다.

기간제(`term_*`, `licenses.term_ends_at`)와 연 구독(`sub_yearly`) 열·크레딧 지급량은 가격 확정(ADR-001 Q3) 후 추가한다. 위 `seats`·`web_studio`·`web_sessions_max` 값은 제안이며 `web_sessions_max`는 ADR-001 Q6 미결이다.

## 9. 도면 자동 생성 (2026-10-16 추가)

사용자 결정(2026-10-16): 사용자가 CAD처럼 선을 직접 그리지 않고, 대지·법규·매스·실 프로그램 같은 정보를 입력하면 앱이 도면을 자동으로 그린다(파라메트릭 방식). 오토캐드·라이노 같은 상용 CAD를 앱에 넣거나 설치를 요구하지 않고, 결과를 DXF로 내보내 사용자가 자기 CAD에서 이어서 작업하게 한다. 이 장은 1~8장 형식을 따르되 기존 장의 줄을 옮기지 않으려고 파일 끝에 덧붙였다(`docs/file/03-설계/공용코어/DOC_TEMPLATE.md:356`). 1~8장과 충돌하면 이 장의 도면 관련 항목이 우선한다.

### 9.1 원칙과 입력 경로
