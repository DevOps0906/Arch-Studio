## 3. 도면 주석 규칙 — 3.8절 "미리보기" 행과 개발서 12장에 반영

### 3.1 원칙
1. 자동 작도 레이어(A-SITE-BNDY·A-SETBACK·A-MASS·A-DIMS 등)는 편집 화면에서 잠금·회색(`--color-concrete`)으로 보이고 도구가 집지 못한다. 형상은 고칠 수 없다(기존 원칙 유지).
2. 사람이 만든 주석은 레이어 `A-ANNO-USER` 하나에만 들어간다(DXF 매핑 표에 행 추가, 사무소 매핑에서 이름 변경 가능).
3. 기존 `SheetSpec.annotation_overrides`(자동 주석의 위치·문자·숨김)와 새 사용자 주석을 **`SheetSpec.annotations[]` 하나로 합친다**(결정 2). 저장은 모델(로컬 `sheets`)이며 도면 파일이 아니다.
4. 출력 = `drafting(model, sheetSpec, profile)` 순수 함수. 같은 모델·같은 `annotations[]` → 같은 바이트.

### 3.2 `annotations[]` 스키마 제안 (zod, `packages/domain/src/sheet.ts` 변경 후보)
```ts
const anchorSchema = z.object({
  ref: z.string(),                       // 모델 객체 ID (예: "mass-1", "site", "room-3")
  part: z.enum(["vertex", "edge", "center"]),
  index: z.number().int().nonnegative().optional(), // 꼭짓점·변 번호(엔진 정렬 순서 기준)
  at: z.enum(["start", "end", "mid", "foot"]).optional(), // 변 위 위치, foot = 상대 앵커에서 내린 수선의 발
}).strict();

const annotationSchema = z.discriminatedUnion("kind", [
  // 기존 annotation_overrides를 옮긴 것: 자동 주석 1개를 옮기거나 문구를 바꾸거나 숨긴다
  z.object({ id: z.string(), kind: z.literal("override"), target: z.string(),
    dx_mm: z.number().optional(), dy_mm: z.number().optional(),
    text: z.string().optional(), hidden: z.boolean().optional() }).strict(),
  // 사람 치수: 값은 엔진이 두 앵커 사이 거리로 계산한다(사람이 숫자를 넣지 않는다)
  z.object({ id: z.string(), kind: z.literal("dim"), a: anchorSchema, b: anchorSchema,
    offset_mm: z.number(), text: z.string().default("{값}") }).strict(),
  // 문자·지시선·구름: 앵커 + 용지 mm 오프셋
  z.object({ id: z.string(), kind: z.enum(["text", "leader", "cloud"]), anchor: anchorSchema,
    dx_mm: z.number(), dy_mm: z.number(), text: z.string(),
    size_mm: z.number().optional() /* 구름 크기 */ }).strict(),
]);
// SheetSpec: annotation_overrides 제거 → annotations: z.array(annotationSchema)
```
- 오프셋 단위는 **용지 mm**(AR-06-020 [DECISION] 후보와 같은 기준)로 하고 저장 전에 0.1mm로 반올림한다. 앵커가 있어 모델이 바뀌어도 주석이 따라간다. 사용자가 고르는 위치는 화면 좌표가 아니라 앵커와 오프셋이다.
- 서체·크기·색은 DraftingProfile에서만 정한다(주석마다 두지 않는다).
- 이행: 기존 `annotation_overrides[i]`는 `{ id: "ov-" + target, kind: "override", ...}`로 1:1 변환한다. 이것은 스키마 변경(외부 계약)이라 위험도 높음 → 착수 전 challenger, 계약 테스트 corpus(`apps/api/tests/contract/corpus/sheet_spec.json`)도 같이 갱신한다.

### 3.3 고아 주석 (결정 5)
- 앵커의 `ref`가 모델에 없거나 `index`가 범위를 벗어나면 그 주석은 **고아**다. 위치를 추측하지 않는다.
- 고아 주석은 **출력(DXF·PDF·SVG·PNG)에서 뺀다.** 편집 화면에서만 빨간 파선(`--color-danger`)과 "앵커 없음"으로 보이고, 목록에 "주석 4 · 고아 1"처럼 수를 적는다. 행동은 [앵커 다시 고르기]·[삭제] 두 가지.
- 내보내기 대화상자에 "고아 주석 1개는 출력에서 빠집니다"를 적는다(막지는 않는다). 기존 `unapplied`(적용 못 한 override) 목록과 같은 경로로 보고한다.

### 3.4 결정성 점검 (개발서 12.4절 점검표에 추가)
- 주석 그리기 순서는 `id` 사전순으로 고정한다(배열 순서와 무관).
- 앵커 좌표는 엔진 기하에서 계산하고 mm 정수 규칙을 따른다. 치수 문자의 `{값}`은 엔진 반올림 규칙으로 채운다.
- 주석이 없는 시트의 출력은 지금 골든과 바이트가 같아야 한다(회귀 0). 주석 포함·고아 포함 골든을 새로 추가한다.
- 편집 화면 상태줄에 출력 지문(해시 앞자리)을 보여 주어 "같은 입력이면 같음"을 사람이 확인할 수 있게 한다(선택).

## 4. 3.5·3.7·3.8절 ASCII 도의 교체
세 절의 ASCII 도는 1절 공통 셸 그림 하나로 대체하고, 각 절에는 1.1 표의 해당 열(도구·목록·캔버스·맥락 도구줄·속성)만 남긴다. 영역별 데이터·크레딧 표는 그대로 둔다.
