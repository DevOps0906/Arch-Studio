Content-Length가 manifest.bytes와 다르면 읽기 전에 거부. | P10 | **라이선스 연동 우회**: 화면(XSS)이 자격을 위조하거나 Rust 검사를 건너뛰고 워커에 팩을 넣는다 | 자격 판정은 Rust가 라이선스 파일을 직접 검증한 결과로만(화면은 파일 문자열만 넘김, 판정값을 넘길 수 없음). 서버는 `arch.eligible_rule_packs(p_org)`(DB 판정)·member+ 역할로만. **방어 부족**: 워커 `load_rule_pack` 메시지는 화면 JS가 보내므로 XSS는 검증 안 된 팩을 워커에 넣을 수 있다(로컬 판정 표시만 바뀜, 서버 클라우드 검토는 서버가 재계산 — 02장 4절) | Rust: 라이선스 없음·서명 불일치 라이선스 → `not_entitled`. 웹: 자격 0행 → `AR011` |
| P11 | **무결성 해시**: 해시 형식 혼동(대문자·공백), 해시만 맞추고 크기 다름 | sha256 소문자 hex64만, `bytes` 정확히 일치, 둘 다 서명 범위 안. 서버는 DB·매니페스트 값 비교 | Rust: 크기만 다름 → `content_mismatch` |

| P13 | **IPC 남용**: 반복 호출로 디스크 채우기, 동시 설치 경합, 오류로 내용 누출 | 명령 2개(`rule_pack_install`·`rule_pack_load`)만 capability에 추가, 인자는 문자열만(경로·URL 없음), 입력 상한 파싱 전 검사, 설치는 뮤텍스로 한 번에 하나, 같은 버전은 덮지 않음(최대 설치 수 = 서명된 버전 수). 오류는 상태 이름만(서명·본문·경로 없음) | IPC: 상태 이름만, 경로 인자 없음, 등록 안 된 명령 거부 |

### 방어 부족(수용·후속) 요약
- P4 서명된 철회 목록 없음(롤포워드만).
- P9 최고 버전 하나만 공급(옛 버전 고정 프로젝트는 대체 경고).
- P10 화면 JS가 워커에 직접 팩을 넣는 경로(XSS 전제)는 막지 못한다.
- P14 레이트리밋·URL 캐시 메모리 구현(운영 전 교체).
- P16 Rust 업데이터 미연결.
- 앱 데이터 폴더를 지우면 롤백 기준(설치된 최고 버전)이 사라진다(로컬 사용자 자신만 가능, 이득 없음).
- 단가표는 서명이 없다(TLS·서버 자격 판정만, sha256은 표시용).

## [DECISION]
- D1 서명 매니페스트 저장 위치: 저장소 `arch-releases/rule-packs/<version>/manifest.json`(팩 옆). DB 스키마 변경 없음. 서버는 `sig = rule_packs.signature`, `kid = rule_packs.kid`, manifest의 version·sha256·bytes·kid = 행을 대조하고 원문 그대로 준다(041 D2 합의 이행).
- D2 웹 서버는 팩 서명 키를 갖지 않는다. 02_ARCHITECTURE 442행("`LICENSE_SIGNING_PRIVATE_KEY`가 규칙 팩 매니페스트도 서명")과 다르다 — 041이 고리를 분리했고(라이선스 키와 다른 키), 서버 노출을 줄이려고 서명은 운영 도구(`RULEPACK_SIGNING_PRIVATE_KEY`, 운영 PC·CI)로 옮겼다. **사람 판정(C-3)**: 팩 서명 키 규격·보관 위치.
- D3 내려받기(HTTP)는 화면 쪽 fetch, 검증·설치는 Rust. 이유: Rust에 HTTP/TLS 스택(reqwest+rustls 등) 새 의존성 회피, 받은 바이트는 Rust가 종단 검증하므로 전송 경로를 믿지 않는다. 대가: CSP `connect-src`에 저장소 출처(`https://<project-ref>.supabase.co`)가 필요(현재 tauri.conf.json에 없음 — 배포 설정 때 058).
- D4 오류 코드: AR063 팩 없음, AR064 검증 실패, AR065 자격 없음. AR062는 029 제안(DXF)에 남겼다. 팩 형식(zod) 실패·버전 불일치도 AR064.
- D5 불러오는 팩은 최고 버전 하나(P9 방어 부족). 철회는 롤포워드(P4).
- D6 서명 URL 수명은 데스크톱·스튜디오 모두 10분(04_API의 스튜디오 15분 제안은 미구현). 레이트 리밋(시간당) 목록 120·다운로드 30·단가표 120·업데이트 60 — 제안값.
- D7 라우트 권리: member+ 역할 + DB 자격 RPC만. 04_API 1장 권리 표(`cloud_review`·`desktop_edit` 권리, 402 `fallback`)는 074 권리 합성 전이라 적용하지 않았다(폴백 조직은 RPC가 마지막 자격 팩만 준다).

## 문서와 다르게 한 점
- D2(웹 서버 서명 안 함), D3(Rust가 HTTP를 하지 않음), D6(스튜디오 15분 미구현), D7(라우트별 right 미적용).
- 04_API 2.3절 업데이트 매니페스트 URL "10분(제안)"은 같게 했고, `notes`가 null이면 빈 문자열.
- 팩 본문 상한 64 MiB(041 제안) → 8 MiB.
