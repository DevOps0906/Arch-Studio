## 2. 설계 결정·문서와 다른 점
- **웹 온보딩 경로**: 06장 행·04장 응답 예시는 `/onboarding`이지만 03장 1.3절이 웹은 `/login?step=terms`로 정했다 → 웹은 03장을 따르고, 데스크톱 finish(`/api/auth/finish`)는 `next: '/onboarding'`을 준다. 응답에 `needs_onboarding` 불린을 더했다(04장 응답에 없는 필드, 추가만).
- **finish 응답의 `session`**: 04장은 `SessionContext`. 이메일을 빼고(최소 수집) user_id·display_name·platform_role·status·org·plan_code·entitled·credit_balance를 준다.
- **dev/login 응답**: 폼(화면) 303, JSON(E2E) 200 `{next, …}`. 쿠키는 `@supabase/ssr` 서버 클라이언트가 쓴다. finishLogin은 같은 요청의 쿠키 재읽기에 기대지 않으려고 방금 발급한 access token의 Bearer 클라이언트로 돈다(토큰은 요청 처리 동안 메모리에만).
- **`/api/dev/login` 메서드**: GET·PUT·PATCH·DELETE·OPTIONS·HEAD도 export해 판정 거짓이면 404(405로 존재가 드러나지 않게), 참이면 405.
- **CSRF 판정**: Next 서버의 `req.url` 호스트가 실제 Host와 달라 같은 출처 요청이 403이 되는 것을 실측 → Origin을 `Host` 헤더와 비교하고, Origin 호스트 이름은 loopback만(DNS 리바인딩 차단).
- **가입 크레딧(D-H2)**: 휴대폰 본인인증 연동 없음. 현재 DB는 bootstrap 때 가입 크레딧 30을 멱등 키 `signup:<org>:arch`로 지급하므로 "원장 1행" 기준은 이 키에 기대어 있다. 본인인증 후 지급으로 바꾸는 것은 074.
- **Vite `import.meta.env.DEV`는 `NODE_ENV`를 따른다**(실측: `NODE_ENV=development`면 `--mode production`이어도 DEV=true). 그래도 릴리스 빌드는 `desktopEnvGuard`가 `VITE_AUTH_MODE=mock`을 막아 조건이 거짓이다. 릴리스 CI는 `NODE_ENV=production`·`VITE_AUTH_MODE=live`를 명시하고 `check-bundle-mock.mjs dir apps/desktop/dist`를 돌릴 것.
- **서버 번들의 시드 이메일**: 웹 서버 청크(`.next/server`)에는 `personas.ts`의 `@dev.test` 문자열이 남는다(판정 거짓이면 쓰이지 않음, 404). 클라이언트 번들(`.next/static`)은 0건(확인). 데스크톱 릴리스 번들은 청크 자체가 빠진다(확인).
- **`process.env.NEXT_PUBLIC_SUPABASE_URL` 이중 확인**: Next 16 서버 번들에서는 치환되지 않음을 실측(원격 URL로 빌드 + 실행 env 로컬 → 판정 참). 서버의 Supabase 클라이언트도 실행 env를 읽으므로 같은 값이다.
