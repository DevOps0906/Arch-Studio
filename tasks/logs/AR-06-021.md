## 결정·가정(팀장 확인 필요 표시)
- 좌표: 첫 뷰 모델 mm 그대로, 용지 요소는 `(용지 − 첫 뷰 origin) × 분모/100`. 뷰가 여럿이면 각 뷰 origin 차이만큼 이동. 용지 쪽 INSERT도 블록 배율 1.
- 시각: `$TDCREATE`·`$TDUPDATE`(율리우스일)를 항상 쓰고 기본값 2451545(엔진은 시각을 읽지 않음). `julianDate(epochMs)` 제공. 숫자 규칙상 소수 3자리(약 86초 해상도).
- 핸들: 구조 핸들(테이블·레코드·OBJECTS)을 먼저 고정 순서로 선할당, BLOCKS·ENTITIES는 쓰는 순서. TABLES가 OBJECTS 핸들(340·390)을 참조해 순수 순회 순서 할당은 불가.
- 선 종류 패턴을 용지 mm(DASHED 3,−1.5 / DASHDOT 3,−1,0,−1)로 두고 `$LTSCALE` = 축척 분모(1/200에서 스파이크 값 600·300과 같음).
- ANSI31: 패턴 배율 = 분모(출력 간격 3.175mm). SOLID·ANSI31 외 패턴 없음(계약).
- 글꼴: 기본 `malgun.ttf`/`Malgun Gothic`(스파이크 AutoCAD 확인). `DraftingProfile.font_family` → TTF 대응표는 없음 — **팀장 확인 필요**.
- 20MB 초과는 예외가 아니라 `too_large: true`(DraftingErrorCode에 해당 코드가 없고 errors.ts는 020 계약이라 안 바꿈).
- `.gitattributes` eol=lf 지시에 따라 골든 DXF는 LF로 저장, 비교는 LF 정규화 후. CRLF는 단위 테스트가 검사. ezdxf audit은 LF 골든 대상(정확한 CRLF 바이트로 두려면 `-text`가 대안).
- 골든 갱신 강제: `update.ts`는 기존 골든과 다르면 `DXF_WRITER_VERSION`을 올렸을 때만 덮어씀. 테스트는 meta.writer_version = 상수, input.json·meta.json = cases.ts 재생성 결과를 검사(020 시트 모델이 바뀌어도 버전 올림 필요).

## 리뷰 반영 (2026-10-29)
- layers: FORBIDDEN에 제어 문자(\u0000-\u001f, \u007f) 추가. 레이어 이름은 ASCII 대문자 키로 비교, 예약 "0" 포함. 철자가 정확히 같으면 합치기(기존 규칙 유지), 대소문자만 다르거나 "0"이면 `name_conflict` 경고 + 나중 쪽 표준 이름 복귀(복귀 이름도 앞 이름과 대소문자만 다르면 앞 이름에 합침). 작성기는 출력 표 대소문자 무시 중복을 다시 검사(INVALID_ARGUMENT).
- 골든: `writer-layer-map-control-chars` 추가(25건). DXF는 `.gitattributes` `**/*.dxf -text`로 CRLF 원시 바이트 저장·비교. `_harness/manifest.json` = DXF_WRITER_VERSION + DXF sha256(버전 그대로 해시가 바뀌면 테스트 실패, update.ts는 버전이 오르거나 최초일 때만 재작성, 새 케이스는 항목 추가만). 기존 골든은 내용 동일·저장 형식만 CRLF로 재생성, manifest 최초 작성.
- golden.yml 액션 SHA 고정(git ls-remote로 확인): checkout v7.0.1, setup-node v7.1.0, setup-python v7.1.0, pnpm/action-setup v6.1.0(주 버전이 v5·v4에서 올라감 — 입력 호환은 CI 실행으로 확인 필요).
