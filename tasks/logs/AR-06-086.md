# AR-06-086 도면 주석 편집층

## [DECISION] 착수 전 (2026-11-02, 팀장 + 사용자) — challenger REVISE 반영
1. 골든(사용자 결정): 주석 없는 시트는 DXF·PNG 바이트 동일. SVG·PDF는 `input_hash` 관련 줄(data-input-hash·PDF 파일 ID)만 달라지는 것을 허용 — 해시 외 차이 0을 diff로 증명하고 커밋 본문에 이유를 적는다. golden input.json 4개는 새 키로 갱신.
2. `annotations`는 optional. 빈 배열은 정규화 시 키 생략(canonical에서 제외). 옛 `annotation_overrides` 키는 strict 스키마에서 거부하고 이행 함수만 받는다.
3. `A-ANNO-USER`는 표준 레이어 표(STD_LAYERS·pydantic StdLayer·DB v_std)에 넣지 않는다. 사용자 주석이 있을 때만 DXF LAYER 표에 추가 → 주석 없는 DXF 바이트 동일. 사무소 매핑 이름 변경은 후속(DB 마이그레이션 필요, 기록만).
4. 저장 이행: localStorage 키 `arch.sheets.v2.<id>` 신설, v1은 읽기만(덮어쓰기·삭제 0). 이행은 parse 안에서, **시트 단위 실패 격리**(한 시트가 깨져도 나머지 유지, 깨진 원본은 v1에 그대로 남김). projects/index.tsx:126 읽는 곳도 같은 함수로. SQLite `sheets.annotation_overrides` 칼럼은 미사용이라 손대지 않음(기록만). Supabase에는 SheetSpec 저장 테이블 없음.
5. 1:1 이행 id: 같은 target의 override는 기존 병합 결과 하나로 `ov-<target>`. `note:<id>`는 text 주석 `note-<id>`. 중복 id는 zod·pydantic 모두 거부(corpus 사례 추가). 정렬은 기존 `cmpStr`.
6. 고아 판정: 앵커 ref 없음·index 범위 밖·이 시트에 그려지지 않는 객체 → 고아. 다중 앵커 주석은 하나라도 고아면 전체 고아. override target 없음은 기존 `missing_target` 유지, 새 사유 `orphan_anchor` 추가(워커 응답 계약 drafting.handlers.ts 갱신). 정점 수 변경으로 index가 다른 정점을 가리키는 경우는 후속(안정 정점 id 필요, 기록만). 모델 재생성 시 객체 id 유지 여부도 후속 확인.
7. 용지 mm: 기존 해상도 0.01mm 유지(r(v*100)), 1:1 이행 보장. center·at 규칙은 bbox 중심 + 0.01mm 반올림.
8. 상한(zod·pydantic 동일): 주석 500개, 문구 200자, cloud 정점 64, leader 정점 16. 사용자 문구는 기존 note 경로의 이스케이프·checkValueText를 그대로 거친다.
9. zod↔pydantic 동치: 정규화기에 oneOf·discriminator 처리를 추가하되, 일부러 어긋난 스키마를 잡아내는 음성 테스트를 함께 추가(테스트 완화 금지). contract.test.ts 스냅샷 갱신.
