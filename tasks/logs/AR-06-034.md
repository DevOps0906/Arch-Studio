## 결정·이유
- **행 작업은 "관리" 하나 → 오른쪽 시트.** 처음에는 행마다 이력·이름 바꾸기·삭제 버튼 3개를 뒀으나 1400px에서도 표가 잘렸다(스크린샷). 패턴 G "삭제 등 위험 행동은 메뉴 안쪽"·B "상세는 옆 시트"에 맞춰 시트로 옮김.
- **판정 요약 배지·시트 수 열 없음**(3.3절 목록 열과 다름): 070 ProjectStore에 `judgment_snapshots`·`sheets` 조회가 없다. 8.6절 "수집하지 않은 지표의 0 표시 금지". 조회 경로가 생기면 열 추가.
- **"오늘 처리할 일"**: 근거 있는 3종만(열람 모드 = desktop_edit 거부, 폴백 = cloud_review 사유 fallback, 이 세션의 저장 충돌). 클라우드 검토 결과·실패 AI 작업·개정 n건·체험 만료 임박은 조회 경로가 없어 만들지 않음. 0건이면 **큰 EmptyBlock 대신 한 줄 빈 상태**(지시는 EmptyBlock이었으나 홈 맨 위 큰 점선 상자가 목록보다 무거워 보였다 — 8.5절 "주인공은 목록", "0이면 칩을 숨긴다"). AR061은 맨 위 배너, AR060은 목록 자리 복구 안내가 맡고 오늘 처리할 일에서는 뺐다(중복). AR060이면 오늘 처리할 일 블록 자체를 숨김.
- **버전 이력**: 070 ProjectStore에는 리비전 목록·열기 메서드가 없다(4개뿐). 저장소가 `listRevisions(id)`·`openRevision(id, version)`을 구조적으로 가지면 쓰고, 없으면 "지금 버전 vN + 이 빌드는 이전 버전 목록을 아직 읽지 못합니다"(조용한 빈 목록 금지). 데모는 세션 이력 픽스처(SessionHistory: 본·저장한 리비전만 기억). **요청(006·070)**: Rust `local_db_list_revisions(id)`·`local_db_get_revision(id, version)` + ProjectStore 메서드. 복원은 항상 새 버전 저장.
- **충돌 대화상자**: 두 선택만. 클라우드 = "내 변경을 사본으로 저장"·"서버 최신 열기"(문서 그대로). 로컬 VERSION_CONFLICT는 서버가 없어 두 번째를 "저장된 최신 열기"로 표기(문서와 다른 점). 사본 = 새 UUIDv7 + 이름 "<이름> (내 변경)"(120자 넘으면 원래 이름을 줄임) + expectedVersion null. 삭제 충돌은 사본으로 저장할 "내 변경"이 없어 대화상자 안 오류 + 목록 새로 고침.
- **새 프로젝트 최소 입력**: 이름(120자 = cloud_projects 이름 CHECK에 맞춤, 로컬 200자보다 좁게)·대지 이름(선택 200자)·용도지역(21종 선택)·대지 가로·세로(m, 소수 둘째 자리, 1000m 이하). DesignModel v1은 필수 필드가 있어(경계 3점 이상·용도지역) 사용자가 넣은 가로·세로로 원점 반시계 직사각형(mm 정수)을 만든다(LLM·추정 좌표 0). rule_context는 빈 값(대지 탭에서 정함), engineVersion·meta = `projects-new-1`(엔진 계산이 아닌 빈 모델 표식).
- **"샘플 대지로 시작"은 비활성 + 이유**: 샘플 묶음이 데모 모듈(릴리스 0)에만 있다. 샘플 배포 경로는 별도 작업.
- **편집 권리 키 = `desktop_edit`**: 만료·unverified면 새 프로젝트·이름 바꾸기·삭제·복원 비활성 + 잠금 안내(숨기지 않음), 목록·이력 보기·열기는 된다. 설치형 실제 빌드는 041·074 전까지 unverified라 잠김이 정상(셸 README 경고).
- **미리보기 `?state=`는 데모 모드에서만** 읽는다(`useDemoMode()`): loading·error·empty·conflict·conflict-cloud·ar060·ar061·manage. 릴리스 화면은 데이터 상태로만 그린다. 데모 픽스처 파일은 demo/ 모듈·DEMO_MARKER를 import하지 않는다(릴리스 번들 검사).
- **클라우드 사본 칩**: 로그인·온라인이면 `GET /api/cloud-projects`(api-client, parse 훅). 확인됐고 사본 있음 = "이 PC vN · 클라우드 사본 vM", 확인됐고 없음 = "이 PC에만 · vN", 확인 못 함 = "이 PC · vN"(사본이 없다고 단정하지 않음). 로그아웃·오프라인 = "로그인하면(인터넷 연결 후) 클라우드 작업이 보입니다". 업로드·내려받기 버튼은 077.

## 서버(클라우드 사본 API)
- 순서(POST): 세션(Bearer, `gatewaySessionResolver`) → 본문 4KB 상한·zod strict(org_id·user_id·모르는 키 422) → 레이트(조직 60/분) → member+ → entitled(402 can_download) → web_edit(074 주입 시, fallback 사유 구분) → 경로 = `isServerUploadPath(project_snapshot)` + 첫 폴더 세션 조직 + 프로젝트 폴더(local_id ?? project_uuid) → 업로드 객체 재검사(없음 23514, 100MB 초과 AR031) → 저장소 save → **응답 project_uuid·version이 요청과 expected+1이 아니면 500**(조용한 덮어쓰기 방어).
- DB 오류: 저장소가 `CloudDbError(code, {currentVersion|max})`로 던진다. AR041 → 409 `details.current_version`, AR040 → 403 `details.max`. 원문 예외는 internal(응답·로그에 원문 0).
- GET: 402 예외(entitled=false 허용), member+, 쿼리는 `cursor`만(base64url 200자), 행 org_id ≠ 세션 조직이면 버리고 개수만 경고 로그, 응답에 org_id 없음.
- upload-url: `uploads/sign`(project_snapshot, project_ref = id)으로 넘기는 별칭. 새 사본(조직에 id 행 없음)이고 상한에 닿았으면 서명하지 않고 AR040.
- 로그: 허용 목록(`route·code·status·project_uuid·version·count·reason`). 이름·경로·커서·토큰 0(테스트).

## 073과의 경계 (DB 미연결)
- `deps.ts`의 저장소(`CloudProjectRepo`: list·usage·find·save)와 업로드 재검사(`SnapshotInspector.inspect`)는 **미연결 자리표시자 → 501 not_implemented**. 조용히 빈 목록을 주지 않는다.
- 이유: 현재 `2400_arch.sql`의 `arch.cloud_projects`는 `local_id not null`·`unique(org_id, local_id)`이고 `save_cloud_project(p_local_id, p_name, p_storage_path, p_expected_version)` 옛 시그니처다. 04장 계약(`project_uuid` 정본·`local_id` nullable·`(org_id, project_uuid)` 업서트·`p_project_uuid` 인자)은 073의 새 마이그레이션 몫. 스키마·마이그레이션은 고치지 않았다.
- 073이 할 일: supabase 구현 2개를 deps.ts에 넣기 — list(SELECT, updated_at desc + 커서, bytes 열 필요), usage(count + `arch.feature_int(org_features, 'cloud_projects_max')` + retention_until), find, save(RPC → PostgREST 오류 `AR040`·`AR041`·`23514`·`42501`·`22023`을 CloudDbError로, AR041 현재 버전은 오류 detail/hint로 받는 방식 결정), inspect(service_role Storage `arch-user` 객체 메타 크기). AR040 수치 `max`도 RPC가 알려 줘야 한다.

## 통합 시나리오 목록(073 연결 후 실 DB로)
1. 새 사본 expected 0 → v1, 같은 요청 재전송 → 409 AR041, 행 1개·버전 1 그대로.
2. 기존 v3에 expected 2 → 409(current_version 3), 이름·storage_path·version 변화 0. expected 3 → v4.
3. 체험 조직(cloud_projects_max 3)에서 4번째 새 사본 → 403 AR040, 행 수 3 그대로. upload-url도 같은 조건에서 서명 0.
4. 다른 조직 사용자 JWT로 GET → 상대 조직 행 0건(RLS). 같은 project_uuid를 두 조직이 써도 각자 행(유니크 (org_id, project_uuid)).
5. 다른 조직 경로(`<other_org>/arch/project_snapshot/...`)로 POST → 422 23514, RPC 호출 전 거절. 경로 조작(`..`, 다른 목적 폴더) 동일.
6. 업로드 안 한 경로로 POST → 422. 100MB 초과 객체 → 413 AR031.
7. entitled=false(만료) → GET 200, POST 402(can_download true), upload-url 402. 폴백 조직(web_edit fallback, 074) → POST 402 reason fallback.
8. viewer 역할 → GET·POST 403.
9. 동시 저장 2건(같은 expected) → 하나만 성공, 다른 하나 AR041(advisory lock + version 비교).
10. 충돌 2선택: "내 변경을 사본으로 저장" = 새 project_uuid expected 0 → 새 행, "서버 최신 열기" = GET 최신 version.
11. 응답·서버 로그에 이름·경로·토큰·SQL 원문 0.
