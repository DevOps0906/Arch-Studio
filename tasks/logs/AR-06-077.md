# AR-06-077 로컬 ↔ 클라우드 수동 업로드·내려받기(설치형)

## 구현 (2026-11-03, builder)
- `packages/features/src/cloud-sync/` `CloudSync`(포트 주입: 로컬 ProjectStore·CloudLinkStore·CloudProjectStore). 결과는 `kind`(uploaded·downloaded·conflict·offline·not_found).
  - 최초 업로드: 새 project_uuid(UUIDv7) 사본 + `local_id` 전송 → 성공 후 연결 기록. 재업로드: 연결 uuid에 expected_version = 연결 version → 같은 행 version+1(local_id 재전송 없음, 서버가 유지).
  - 원본 로컬 유지: 업로드는 로컬 리비전을 만들지 않는다.
  - 충돌(AR041·23505) → 저장 안 함 + 2선택. "내 변경을 사본으로 저장" = 새 uuid 사본(local_id 없이, 연결 그대로). "서버 최신 열기" = 서버 최신을 연결된 로컬의 새 리비전으로(이전 로컬은 리비전 이력에 남음) + 연결 version 갱신.
  - 연결 유실 + 서버에 같은 local_id 사본(23505) → 그 사본과의 충돌로 2선택. 서버 사본이 지워졌으면(NOT_FOUND) 업로드가 새 uuid로 다시 만들고 다시 연결.
  - 클라우드 모드 오프라인: `openCloud` 읽기 전용 + 안내 문구, `saveCloud`·`upload`는 네트워크 0으로 offline. `download`("로컬로 복사해 편집")는 읽기 캐시로 가능, 권리(402) 검사 없음.
- `packages/shell-bridge`: `CloudLinkStore`(adapters/cloud-link.ts, 설치형만 `cloudLinks` 선택 필드), `TauriCloudLinkStore`, `CloudProjectStore`(= WebProjectStore + `save(input, {localId})` + `findByLocalId`), `createCloudProjectStore`. 409 23505 → VERSION_CONFLICT. **폴더 키 대조**: 서명 경로의 프로젝트 폴더가 project_uuid가 아니면 PUT·저장 전에 거부(RECONCILE 후속 "local_id 폴더면 422" 해소).
- `apps/desktop/src-tauri`: `local_db_get_cloud_link`·`local_db_set_cloud_link` 명령 2개(0001의 `projects.cloud_project_id`·`cloud_version` 열 사용 → 새 마이그레이션 없음). 같은 사본 version 역행 거절, 없는·삭제 프로젝트 NOT_FOUND, link는 deny_unknown_fields. build.rs·lib.rs·capabilities·권한 toml·capabilities 테스트 갱신.

## 결정·차이 (팀장 확인 필요)
1. 새 Tauri 명령 2개 + capability 2개 = 규칙상 위험도 높음(reviewer security 필요). 인자에 경로·SQL 없음.
2. "내 변경을 사본으로 저장"은 연결을 바꾸지 않는다(서버에서 local_id는 한 사본에만 → 새 사본은 local_id 없음). 같은 로컬을 다시 올리면 또 충돌한다.
3. "서버 최신 열기"는 연결된 로컬 프로젝트를 서버 내용으로 새 리비전 저장(덮어쓰기 아님, 이력 유지). 따로 여는 방식이 맞다면 바꿔야 함.
4. 업로드 성공 뒤 연결 기록 실패 시 다음 업로드는 23505 충돌 → "서버 최신 열기"로 복구.
5. 범위 밖(미구현): 전체 프로젝트 일괄 내려받기(zip·진행률·실패 항목 재시도), 화면(버튼·대화상자) 연결.

## [DECISION] 보안 리뷰(ACCEPT, 🔴0) 후속 반영 (2026-11-03, 팀장 결정)
1. 🟠 건축주 개인정보(client_name·client_contact)는 업로드 사본에서 **기본 제외**(05_DATA_MODEL 2.16 제안 채택). `upload`·`resolveConflict(save_as_copy)`에 `includeClientInfo`(기본 false)를 켤 때만 포함.
2. 🟠 "서버 최신 열기": 이름·대지 라벨·설계 모델은 서버 값, **건축주 정보는 로컬 유지**. 안내 문구·리비전 노트 = "설계 모델은 이력 보존, 건축주 정보는 로컬 유지"(`SERVER_LATEST_NOTICE`).
3. 🟡 클라우드 모드 충돌 2선택 `resolveCloudConflict(input, choice)`(project_uuid 기준): 사본 저장 = 새 uuid, 서버 최신 = 다시 열기(`opened`).
4. 🟡 `openCloud` readOnly = 오프라인 **또는** 읽기 캐시 폴백(`CloudProjectStore.openSourced`의 `cached`).
5. 🟡 Rust DB_READ_ONLY = `AR061`(이미 CODES에 있음, 주석·테스트 추가). `download`·`resolveConflict(open_server_latest)`에서 연결 기록 실패 → `link_failed`("로컬에 저장됐지만 클라우드 연결 실패").
6. ❓ 연결된 사본 NOT_FOUND → 자동 생성 안 함, `needs_recreate_confirm` 반환 → 화면 확인 뒤 `upload(localId, { confirmRecreate: true })`(조직 전환 후 의도치 않은 생성 방지). 위 "결정·차이" 4의 자동 재생성은 이것으로 대체.
