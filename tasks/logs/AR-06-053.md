2. 멱등(🔴1): 키 `voice:<org_id>:<request_id>`. consume_credits가 기존 원장 행(중복)을 돌려주면 **제공자 호출 없이 409 IDEMPOTENT_REPLAY**. 결과 텍스트는 저장하지 않음(원본·결과 미저장 원칙).

4. 마이크 헤더(🔴3): apps/web에는 마이크 UI가 없다(스튜디오는 apps/desktop Vite 웹 빌드, D-071a) → next.config `microphone=()` 유지. 스튜디오 웹 호스팅 헤더는 071, 데스크톱 WebView2 마이크 권한은 실기 확인(사람). UI는 권한 거부·미지원 시 텍스트 입력으로 계속.
5. 차감 직접 호출 검사(🟠): start-run.test.ts 허용 목록에 server/voice를 04_API:14 STT 예외로 명시 추가.
6. oss-voice 인증(🟠): 제공자 프로토콜에 토큰 공급 함수 주입(scope=voice). 실제 제공자·토큰 발급 연결은 후속(가짜만). 과금 경로 킬 스위치 `ARCH_VOICE_STT_ENABLED` 기본 off.
7. intake 연계(🟠): 받아쓰기 결과는 텍스트로 intake(source='chat') 입력에 넣는다(stt_job_id 없음).

9. 읽어 주기(🟡): OS 음성 합성, 한국어 음성 없으면 버튼 숨김 + 테스트. 0크레딧.

## [서버] POST /api/voice/stt (2026-11-02)
- 파일: `apps/web/src/server/voice/{config,provider,magic,service,supabase-repo,deps}.ts` · `app/api/voice/stt/route.ts` · 테스트 `service.test.ts`(17건)·`server/ai/gateway/start-run.test.ts`(STT 예외 허용 목록 = voice/supabase-repo.ts 하나).
- 계약: 본문 = 오디오 바이트(webm·ogg·mp4·wav, 매직바이트 확인), `x-request-id`(또는 `?request_id=`) UUID v4. 200 {text, duration_s, credits:1} / 409 IDEMPOTENT_REPLAY / 413 AR031 / 415 / 402 CR001·entitlement / 503 stt_disabled / 502 stt_failed / 422 stt_too_long·stt_empty.
- 멱등: 키 `voice:<org>:<request_id>`. consume_credits는 중복 시 기존 행을 돌려줄 뿐 알리지 않으므로 서비스가 원장(credit_ledger.idempotency_key)을 먼저 조회한다. 같은 프로세스 동시 중복은 inflight 집합이 막고, 프로세스 간 경합은 DB 멱등 키가 추가 차감을 막는다(제공자 이중 호출은 이론상 남음, 운영 전 DB 쪽 "신규 여부" 반환으로 보강 후보).
- 환불: 제공자 예외·duration>60·빈 전사 → refund_credits 전액(키 `<key>:refund`). 환불 실패는 error 로그만(수동 정산).
- 제공자: 결정적 가짜만. 토큰 공급 함수는 자리표시. 킬 스위치 ARCH_VOICE_STT_ENABLED 기본 off(인증 전 503).
- 알림: 환불된 요청의 같은 request_id 재시도는 409(새 request_id 필요).
