## [서버] POST /api/voice/stt (2026-11-02)
- 파일: `apps/web/src/server/voice/{config,provider,magic,service,supabase-repo,deps}.ts` · `app/api/voice/stt/route.ts` · 테스트 `service.test.ts`(17건)·`server/ai/gateway/start-run.test.ts`(STT 예외 허용 목록 = voice/supabase-repo.ts 하나).
- 계약: 본문 = 오디오 바이트(webm·ogg·mp4·wav, 매직바이트 확인), `x-request-id`(또는 `?request_id=`) UUID v4. 200 {text, duration_s, credits:1} / 409 IDEMPOTENT_REPLAY / 413 AR031 / 415 / 402 CR001·entitlement / 503 stt_disabled / 502 stt_failed / 422 stt_too_long·stt_empty.
- 멱등: 키 `voice:<org>:<request_id>`. consume_credits는 중복 시 기존 행을 돌려줄 뿐 알리지 않으므로 서비스가 원장(credit_ledger.idempotency_key)을 먼저 조회한다. 같은 프로세스 동시 중복은 inflight 집합이 막고, 프로세스 간 경합은 DB 멱등 키가 추가 차감을 막는다(제공자 이중 호출은 이론상 남음, 운영 전 DB 쪽 "신규 여부" 반환으로 보강 후보).
- 환불: 제공자 예외·duration>60·빈 전사 → refund_credits 전액(키 `<key>:refund`). 환불 실패는 error 로그만(수동 정산).
- 제공자: 결정적 가짜만. 토큰 공급 함수는 자리표시. 킬 스위치 ARCH_VOICE_STT_ENABLED 기본 off(인증 전 503).
- 알림: 환불된 요청의 같은 request_id 재시도는 409(새 request_id 필요).

## [리뷰 반영] (2026-11-02, builder) — code·security REQUEST_CHANGES
- 재전송 정책: 서버 오류 응답에 `error.details.refunded`(502 stt_failed·422 stt_too_long·stt_empty). 클라이언트: refunded:true인 stt_failed만 같은 녹음 + **새 request_id**로 다시 보내기. 결과 불명(네트워크·타임아웃·응답 유실)은 같은 id 유지. refunded:false(환불 실패)·409는 재전송 숨김. too_long·empty는 같은 녹음 재전송이 무의미해 숨김(다시 녹음). 409 문구 "결과를 받지 못했다면 다시 녹음… 크레딧 1이 사용되었을 수 있습니다". 통합 테스트 `server/voice/resend.integration.test.ts`(실제 service + api-client + dictation).
- inflight: has·add 동기 처리 후 exists 확인(finally에서 delete). 프로세스 간 이중 제공자 호출은 남는 한계(service.ts 주석) — 운영 전 DB가 "신규 여부"를 돌려주도록 보강 후보.
- 레이트리밋을 본문 버퍼링 전으로(권한·형식·request_id 검사 뒤). 클라이언트 자동 정지 59초(서버 상한 60 유지).
- 환불 실패: 문구 "환불 처리됩니다", 로그에 ledger_id·org_id(전사 텍스트 없음). 전사 중 "전사 취소" 버튼 + AbortSignal 전달. 서버가 안 읽는 Idempotency-Key 헤더 제거(api-client `idempotencyHeader:false`; 중복 합치기는 계속 idempotencyKey).
- **실제 제공자 연결 전 차단 조건(deps.ts 주석에도)**: ① MemoryRateLimitStore는 인스턴스 간 비공유 -> 공유 저장소로 교체 ② 가짜 토큰 "fake-voice-token" -> scope=voice 단기 토큰 ③ 매직바이트는 컨테이너 시작 바이트만 보는 얕은 검사 -> 제공자 디코드 검증.
- 503은 stt_disabled 하나만 쓰며 클라이언트는 모든 503을 "사용 불가"로 단순 취급.
- 검증: apps/web lint·typecheck·test(479), packages/features lint·typecheck·test(360) 통과.
