## [DECISION]
- **D1 규칙 팩 서명 접두 = `"arch-rulepack-v1\n"`**(UTF-8 17바이트, 끝 LF). 서명 입력 = 접두 ‖ manifest 바이트 그대로. 라이선스 접두와 서로 접두 관계가 아님을 테스트로 고정. 키 고리도 분리(`RULEPACK_KEYS`). → **042와 합의 필요.**
- **D2 규칙 팩 서명 매니페스트 형식**: `{ manifest: base64url(JSON 바이트), sig, kid }`, manifest = `{v:1, app_id:"arch", version, published_at(RFC 3339), basis_date, sha256(본문 hex64 소문자), bytes, kid}`. DB `rule_packs.signature`·`kid`는 이 서명·kid, 04_API `/download` 응답은 manifest 바이트(base64url)를 함께 줘야 한다(Rust는 재정준화하지 않으므로 필드만으로는 검증 불가). → **042와 합의 필요.**
- D3 자격(엔진 전달): 라이선스 `valid`만. 영구 = `published_at < (updates_until + 1일) 00:00 Asia/Seoul`(2400 `eligible_rule_packs` 폴백 경계와 같음), 플랜 = `features.rule_pack_updates`. 만료·시계 이상(열람·내보내기만) 상태에서는 팩을 넘기지 않는다(보수적. 열람에 판정 재계산이 필요하면 042·074에서 재검토).
- D4 상태 이름: 04_API `LicenseStatus`의 `valid`·`absent`·`malformed`·`unknown_kid`·`invalid_signature`·`device_mismatch`에 `expired`·`clock_anomaly`를 더했다(둘 다 `license` 요약을 주고 `rights`는 `view_export`만 true). 바깥 kid ≠ payload.kid는 `invalid_signature`, `app_id`·`v` 다름은 `malformed`. 기기 식별자를 못 읽으면 `device_mismatch`(실패 닫힘). → **04_API 2.4 `LicenseStatus` 갱신 필요(docs 소유 밖).**
- D5 경계: `offline_valid_until`·`rights_expiry`는 그 시각 **이전까지** 유효(`now >= t`면 만료). 판정 시각 = `max(now, last_seen)`.
- D6 보수적 기본값: `rights_expiry` 키가 없거나 null이면 영구 = `issued_at` + 30일, 플랜 = 오프라인 한도. 플랜 `offline_valid_until` null이면 `issued_at` + 7일. `rights` 없는 파일(074 이전)은 설치형 편집만 true, 웹·AI·클라우드 false(서버 판정). 설치형 편집 권리가 기한을 넘기면 상태 `expired`. → **074와 합의 필요**(`rights_expiry` null 의미, 기간제 `source`).
- D7 롤백: 통과한 파일 중 가장 늦은 `issued_at`(`max_issued_at`)보다 이른 파일은 `expired`.
- D8 시계 허용 오차 10분(`CLOCK_TOLERANCE_SECS`). 기록 읽기 실패 = 기록 없음(가용성 우선, 공격 이득은 기록 삭제와 같음), 쓰기 실패 무시.
- D9 `build_eligible`: 컴파일 시 `ARCH_BUILD_DATE=YYYY-MM-DD`가 없으면 영구 파일은 false(실패 닫힘). 릴리스 파이프라인이 넣어야 한다.
- D10 `device_hash` = SHA-256(`"com.archstudio.desktop/device-hash/v1\0"` ‖ trim·소문자 기기 ID). 전부 0인 ID·제어 문자·128자 초과는 "읽지 못함".
- D11 모르는 payload 필드는 받아들인다(서명된 서버 값, 앞으로의 필드 추가 호환). 알려진 필드의 중복 키·형식 오류는 거부.

## 서명 규약 일치 확인(교차 벡터)
- 생성: 스크래치패드 스크립트가 040 `createLicenseSigner`·`buildLicensePayload`·`canonicalBytes`로 서명(결과 JSON만 커밋, 개인키 비커밋, 시드 = SHA-256(`ARCH_TEST_ONLY <label>`)).
- 결과: 040이 서명한 정상 파일 6건(영구·체험·구독 확장·유니코드 이스케이프·kid B·비정준 바이트)을 Rust가 `valid`로 검증. 접두 없음·규칙 팩 접두·`v2` 접두·LF 없는 접두 4건은 Node·Rust 모두 서명 거부. Node `kid_mismatch` ↔ Rust `invalid_signature`. 중복 키·다른 앱·다른 버전(서명 유효, Node 참조 검증기는 통과)은 Rust `malformed`. `rights_expiry` 5키 = `issued_at` + 30일, `offline_valid_until` 체험 = min(발급 + 7일, 체험 종료) 값이 그대로 읽힘. `device_hash` Node 계산식 = Rust 계산식.

### 약화 변이 확인(스크래치 복사본, 전부 잡힘)
M1 `verify_strict`→`verify`, M8 `>=`→`>`, 재설정 제거, 재설정에서 `issued > max_issued_at` 제거, `desktop_edit &= build_eligible` 제거, 키체인 형식 오류→Missing, Corrupt 열림 처리, 기록 없음 1일 검사 제거, Unreadable 덮어쓰기, 쓰기 간격 제거, 기기 해시 캐시 제거, 실패 캐시, 운영 슬롯에 픽스처 키(컴파일 실패), `VerifiedLicense` 필드 pub(doctest 실패).

### Windows·macOS 컴파일 검증(한계 포함)
- `rustup target add x86_64-pc-windows-gnu x86_64-pc-windows-msvc aarch64-apple-darwin` 설치됨.
- 크레이트 전체 `cargo check --target x86_64-pc-windows-gnu --lib`는 **실패**: `libsqlite3-sys`(rusqlite bundled) 빌드 스크립트가 `x86_64-w64-mingw32-gcc`를 찾지 못함(C 크로스 컴파일러 없음). 우리 코드 문제 아님.
- 대신 `device.rs`를 그대로 복사한 최소 크레이트(sha2 + `windows-sys =0.60.2` 같은 기능)로 `cargo clippy --target {x86_64-pc-windows-msvc, x86_64-pc-windows-gnu, aarch64-apple-darwin} --all-targets -- -D warnings` 통과. Windows 분기가 실제로 컴파일되는지는 상수 이름에 오타를 넣어 msvc 대상에서만 E0425가 나는 것으로 확인.
- **링크·실행은 미검증**(wine·Windows SDK·mingw 없음). `RegGetValueW` 실제 동작(64비트 뷰·버퍼 크기·반환 바이트 수)은 Windows CI에서 `os_source_*` 형태의 실기 테스트로 확인해야 한다.

### 042·릴리스로 넘김
- 릴리스 파이프라인이 `ARCH_BUILD_DATE=YYYY-MM-DD`를 넣는다(없으면 이제 릴리스 컴파일 실패). 로컬 `tauri build`도 이 값이 필요하다.
- 규칙 팩 롤백·회수 방어(최대 version 단조 기록 또는 서명된 min_version) — 이번에 수정하지 않음.
- Windows/macOS 실제 빌드·실행 CI(`RegGetValueW`·`ioreg` 실기 확인), keyring linux-native(keyutils) 영속성: 재부팅 시 기록이 사라지면 1일 넘은 파일은 `expired`(온라인 refresh 필요) — Linux 설치형을 지원한다면 영속 백엔드 필요.
- 화면 안내: `valid` + `build_eligible=false`(업데이트 기간 밖 빌드), 기록 없음 `expired`(refresh 필요) 문구 — shell-bridge·04_API 2.4 반영.
