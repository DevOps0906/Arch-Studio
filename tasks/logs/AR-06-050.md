## 사람 몫(미완)
- 실제 코퍼스·평가셋 30문항: 픽스처는 모두 `is_example: true`, 수치는 `OO`. 운영 ingest는 예시를 거부한다.
- D-14(공공데이터 출처 표기 의무) 확인 후 `SourceMeta.attribution`을 필수로, `WikiConfig.require_attribution=True`로 바꾼다.
- 운영 임베딩 모델로 재현율 재측정(해시 임베더 수치 1.0은 하니스 동작 확인일 뿐 품질 지표가 아님).

## DB 스키마 제안 (마이그레이션 미작성, 팀장 확인 필요)
core_lite의 `ai_collections`·`ai_documents`·`ai_chunks`·`wiki_pages`로 저장 가능하다. 새 테이블은 필요 없다.
- `ai_collections`: `(org=운영자 조직, app='arch', kind='rag', name='arch.knowledge')` 1행. 플랫폼 공통 지식이라 운영자 조직 소유 + 외부 지식 API 노출(LLM_WIKI.md 3장).
- `ai_documents`: 판 1개 = 1행, `source_type='product'`, `content_hash = document_hash()`, `source_url`·`title`.
- `ai_chunks.metadata`: `to_db_metadata()`(= `model_dump(mode="json", exclude_none=True)`, 되읽기는 `from_db_metadata`). 청크 순번은 `ai_chunks.chunk_index` 컬럼(metadata에 넣지 않음, 추가 키는 strict 거부).
- 검색 함수 제안(새 번호 마이그레이션):
  ```sql
  -- arch.match_knowledge(query vector(1024), application_date date, jurisdiction text, k int)
  -- where collection = arch.knowledge
  --   and (metadata->>'effective_from')::date <= application_date
  --   and (metadata->>'effective_to' is null or application_date < (metadata->>'effective_to')::date)
  --   and (metadata->>'jurisdiction' is null or metadata->>'jurisdiction' = jurisdiction)
  --   and not (metadata->>'is_example')::boolean
  -- order by embedding <=> query, id limit k
  ```
  필터가 HNSW 뒤에 걸려 k개 미만이 나오지 않도록 pgvector 0.8 `hnsw.iterative_scan` 사용 여부 확인 필요. 필터 컬럼을 `ai_chunks`의 실제 컬럼(effective_from/effective_to/jurisdiction)으로 올릴지는 공용 코어 변경이라 팀장 결정.
- 위키 확인일: 지금은 본문 `## 출처` 항목의 `확인일: YYYY-MM-DD`로 강제(lint). 컬럼으로 올리려면 `wiki_pages.confirmed_on date`(제안).
