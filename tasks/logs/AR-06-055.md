## 2. 결정

- [DECISION] request_id: 결과를 모르는 실패(네트워크·스트림이 done 없이 끊김·409 처리 중)만 같은 id를 남기고 같은 질문 재전송에 재사용(서버가 저장 답 재송출, 0크레딧). 확정 실패(환불된 502·504·422, CR001, AI_DAILY_LIMIT)는 다음 전송이 새 id(같은 id는 409가 되므로). 409는 "다시 확인"(같은 id)·"새 요청으로 보내기"(새 id) 두 버튼. 검토도 같은 규칙(start_ai_run 같은 id = 기존 실행).
- [DECISION] 검토 AI 문장에 숫자(아라비아·전각·원문자·로마 숫자)가 있으면 그 문장을 그리지 않는다(서버 validate_free_text 이중 방어). 출처가 하나도 풀리지 않는 문장도 숨기고 "숨김 안내" 한 줄만.
- [DECISION] 위키 페이지 칸 이름(`body_md, sources[{title,checked_at,url?}], links[{label,slug?}], revisions[{date,sections}], checked_at, stale`)은 04_API 문장에서 정한 제안값. 서버 경로가 생기면 맞춘다. 서버 404는 빈 목록으로 숨기지 않고 오류 상태.
- [DECISION] 위키 본문은 마크다운을 HTML로 해석하지 않고 제목·단락·항목 글 블록으로만 그린다(주입 없음, 새 의존성 없음). 출처 링크는 https만.

## 3. 남은 일·팀장 확인 필요

- 셸 오른쪽 채팅 패널: `ChatPanel variant="side"`를 `@arch-studio/features/chat`에서 내보냄. 셸(AppShell)에 패널 자리를 다는 것은 셸 소유(미연결).
- "오늘 남은 <n>턴": 남은 턴을 주는 API가 없다(엔타이틀먼트에 `ai_chat_turns_per_day` 없음, 사용량 조회 없음). 지금은 "1턴 1 크레딧 · 잔액 · 한도는 서버가 확인" 문구 + 429 `AI_DAILY_LIMIT` 안내. 서버에 남은 턴(예: done 이벤트 `turns_left`) 추가 요청.
- 프로젝트 맥락 첨부 체크박스(03장 3.12절): 서버 zod strict 본문에 맥락 필드가 없어 두지 않음.
- 위키 서버 `GET /api/ai/wiki/pages`·`/[...slug]` 미구현 → 실제 모드는 오류 상태. 데모는 목업.
- 데모 fetch(`src/demo/auth.ts`, 셸 소유)에 `/api/ai/chat`·`/api/ai/review`·`/api/jobs` 응답이 없어 데모에서 채팅·검토는 빈 상태(보내면 오류 상태)까지만 보인다.
- 04_API 2.1절 review 행 본문(`judgment`·`model_summary`)과 병합된 서버(`model` 필수, judgment 무시)가 다르다 → 서버를 따름. 문서 정정 필요.
