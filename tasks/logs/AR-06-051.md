### 계약
POST `/graphs/arch.review/runs` (잡 토큰 scope `graph:arch.review`, 토큰 `run` == 본문 run_id). 본문 strict, org 키 거부(org는 토큰에서만). 실행 키 = (job_id, attempt): 같은 attempt 재POST는 기존 실행 반환(202, 재실행 없음), 새 attempt는 새 실행(처음부터), 같은 run_id에 다른 job은 409.
```json
{"run_id":"33333333-3333-4333-8333-333333333333","attempt":1,"application_date":"2025-01-01","timeout_s":600,
 "judgment":{"engine_version":"1.0.0","rule_pack_version":"2025.1","application_date":"2025-01-01","pending_changes":0,
  "items":[{"key":"coverage","verdict":"FAIL","value":65,"limit":60,"unit":"pct",
   "basis":[{"law":"가상건축법","article":"건폐율","effective_from":"2024-07-01","ordinance":false}]}]}}
```
`timeout_s`(1..600, 기본 600)는 시도당 상한 = 전체 10분 중 남은 시간. 응답 202: `{"data":{"graph_run_id","graph","run_id","status":"accepted","attempt":1}}`.

GET `/graphs/runs/{graph_run_id}` 성공:
```json
{"data":{"graph_run_id":"...","graph":"arch.review","run_id":"...","status":"succeeded","attempt":1,
 "result":{"review":{"schema_version":"review.v1","rule_pack_version":"2025.1","disclaimer_version":"arch-review-disclaimer.v1",
   "items":[{"key":"coverage","verdict":"FAIL","engine_value":{"value":65.0,"limit":60.0,"unit":"pct"},
     "sentences":[{"text":"65이(가) 한도 60와 비교됩니다.","source_ids":["law-cov-v2#0"]}]}],
   "needs_check":[],"sources":[{"id":"law-cov-v2#0","law":"가상건축법 건폐율","article":"","effective_from":"2024-07-01","kind":"law"}]},
  "refs":{"coverage.limit":60.0,"coverage.value":65.0}}}}
```
실패: `{"data":{...,"status":"failed","attempt":1,"error":{"code":"AR033","retryable":false,"stage":"interpret"}}}`. code = AR033(false) | PROVIDER(true: LLM·검색 오류·시간 초과) | INVALID_INPUT(false: 날짜 불일치·중복 키). stage = load|retrieve|interpret|compliance. 예외 메시지는 담지 않음. 실행 없음/타 조직/타 잡 = 404(워커는 재시도 가능으로 분류, 결정 7).

## [DECISION] 숫자 차단을 구조로(로컬 6f60630·666c065·217305e 이식, 2026-11-03 RECONCILE 051)
원격(Ed25519 팩 서명·api 배선·(job_id, attempt)·워커 계약)은 그대로 두고 숫자 차단만 로컬 방식으로 바꿨다.
- 고문(advisor) 진단 요지(로컬 재리뷰 우회 2회 뒤): 숫자 표기 블랙리스트(정규식)는 수렴하지 않는다(로마 숫자 Ⅵ·원문자 ⑥·한자 六十·아랍-인도 숫자·"삼 층"·"다섯층"·"삼십 평"·"용적률 이백"이 차례로 우회). 막을 것을 열거하지 말고 허용할 것을 열거한다. 원격의 `{ref:}` 자리표시자 + 맨숫자 정규식도 같은 계열이라 교체.
- 구조: LLM 문장은 `parts: [Text | Ref]`(schema `ReviewLlmSentence.parts`·`ReviewLlmRewrite.parts`). Ref `{item, field}`의 item은 **판정 key**(원격 그래프가 key 단위라 로컬 `items.<i>` 대신)이고 문장이 속한 항목과 같아야 한다. needs_check(·district_plan) 문장은 Ref 금지, 값 없는 칸 금지. 자리표시자 문자열 파싱 제거.
- Text 허용 문자 집합: NFC 정규화 후 한글 음절(AC00–D7A3)만·ASCII 알파벳·공백·고정 구두점. 자모·채움 문자, N*·numeric()≠None·한자·전각·원문자·로마 숫자는 열거 없이 거부(유니코드 전수 테스트).
- 한글 수사 닫힌 집합: 단위어·지표명 바로 앞뒤 낱말(4자 창)이 수사 문법이면 거부. 지표명 뒤 연결어(한도·제한·기준 등 최대 2개, 원형 대조) 건너뛰기, 단위 구간 점유('세대'의 '대'), 예외 낱말(한층·일대). 기존 정규식·ASCII 수 낱말·올바른 꼴 로마 숫자 낱말(m·mm·cm·ID·LLM·mid 오탐 없음)은 보조망.
- 판정기 `validate_free_text` 하나(compliance/arch.py)를 resolve_refs·compliance가 같이 쓴다(같은 판정 테스트). 금지(FAIL) 표현은 원격 규칙 사전(check_text)을 그대로 쓰고 판정기 위반에 넣었다 → 금지 표현도 resolve_refs에서 1회 재작성 대상이 되고, 전부 막히면 AR033 stage는 `interpret`(이전 `compliance`). WARN(단정에 가까운 표현)은 위반이 아니고 compliance가 needs_check로 옮긴다(원격 동작 유지).
- 출력: 숫자는 `ReviewItem.engine_value`·`verdict`로만. 문장 text에 숫자가 없고 Ref는 '산정값'·'한도값'으로 그린다. 문장마다 `nature: 'interpretation'`(기본값). `ReviewRunResult.refs`는 남은 문장의 Ref 경로 `<key>.<field>` → 엔진 값(워커 계약 `{review, refs}` 유지).
- 조문 번호 예외 없음(조문은 sources[].article로만). 정량 템플릿 문장(문구 카탈로그)은 사람 승인이 필요해 만들지 않았다.
- 잔여 위험: 수사 없는 수량 주장("한도의 절반", "곱절", "대부분", "훨씬 넘는다" 등 비교·비율 낱말), 보조망 밖 ASCII 수 표현, 단위어·지표명에서 4자보다 먼 수사. 해석 표식이 붙고 화면 수치는 engine_value에서만 나오므로 영향은 "문장이 수치처럼 읽힐 수 있음"에 그친다. 정량 템플릿 도입 때 다시 본다.
