## [DECISION] 숫자 차단을 구조로(재리뷰 우회 대응, 팀장 결정 2026-11-02)
- 고문 진단 요지: 숫자 표기 블랙리스트(정규식)는 수렴하지 않는다(로마 숫자 Ⅵ·원문자 ⑥·한자 六十·아랍-인도 숫자·"삼 층"·"다섯층"·"삼십 평"·"용적률 이백"이 차례로 우회). 막을 것을 열거하지 말고 허용할 것을 열거한다.
- 구조: LLM 문장은 `parts: [Text | Ref]`. Ref `{item, field}`만 엔진 값을 가리키고 item은 문장 target과 같아야 한다. needs_check·district_plan은 Ref 금지. 자리표시자 문자열 파싱 제거.
- Text는 허용 문자 집합(한글 음절·자모, ASCII 알파벳, 공백, 고정 구두점)만. N*·numeric()≠None·한자·전각·원문자·로마 숫자 등은 열거 없이 거부(유니코드 전수 테스트).
- 한글 수사는 닫힌 집합: 단위어(층·미터·m·%·㎡·평·제곱·배·할·세대·대·개·퍼센트·프로)와 지표명 바로 앞뒤 낱말(4자 창)이 수사 문법이면 거부. 기존 정규식·ASCII 수 낱말·로마 숫자 낱말은 보조망.
- 판정기는 `validate_free_text` 하나(resolve_refs·compliance 공용, 같은 판정 테스트). 위반 → 재작성 1회 → 제거 → 0건이면 AR033.
- 출력: 숫자는 `ReviewItem.engine_value`·`verdict`로만. 문장 `text`에는 숫자가 없고 Ref는 '산정값'·'한도값'으로 그린다. 문장마다 `nature: 'interpretation'`(해석, 수치 아님, 기본값이라 기존 코퍼스 호환). 04_API 4.2절 반영(docs/file·docs/source 두 사본).
- 조문 번호 예외(제N조)는 없앴다: 숫자 문자를 허용하지 않으므로 조문은 sources[].article로만 표시된다.
- 정량 템플릿 문장(문구 카탈로그)은 사람 승인이 필요해 만들지 않았다.
- 잔여 위험: 수사 없는 수량 주장("한도의 절반", "곱절", "대부분", "훨씬 넘는다" 등 비교·비율 낱말), 보조망 밖의 ASCII 수 표현, 단위어·지표명에서 4자보다 먼 수사. 문장에는 해석 표식이 붙고 화면 수치는 engine_value에서만 나오므로 영향은 "문장이 수치처럼 읽힐 수 있음"에 그친다. 정량 템플릿 도입 때 다시 본다.
- 웹 소비 타입: ReviewResultV1을 읽는 TS 코드가 아직 없다(검색 0건). 결과 화면 작업에서 04_API 4.2절대로 만든다.
