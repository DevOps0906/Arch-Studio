## 2. 결정

- [DECISION] 스위치 off = 503 `ai_proposal_disabled`, 인증·본문·DB·Storage 전에 반환(차감 0). 웹·워커 같은 표 `PROPOSAL_CONFIG_CASES`. R-A5 전이라 운영에서는 제공자가 없어 항상 꺼짐.
- [DECISION] 국외 이전 동의(AI002)는 **kind=proposal(서술 LLM 있음)이고 서술 경로가 국외일 때만**. 경로 기본값은 국외(실패 닫힘), `ARCH_PROPOSAL_NARRATIVE_ROUTE=oss`일 때만 생략. 템플릿 문서(overview·area_table·cost)는 LLM이 없어 동의 없이 허용.
- [DECISION] content_sha256 = 정규화 내용 파일 바이트의 sha256. 파일에는 kind·템플릿 버전·content·render_ids·**시트 바이트 sha256**(경로 아님)을 넣는다 → 같은 내용·같은 시트를 다시 올려도 같은 해시 → DB가 doc_template 0크레딧 판정. 워커는 파일 해시 = payload, 시트 해시 = 파일 값을 확인(업로드 뒤 바뀐 시트 거부).
- [DECISION] "같은 버전 재요청 0"은 DB 규칙 그대로 **doc_template만**(start_ai_run proposal 분기). proposal(서술 10)은 같은 request_id 재전송만 0. 04_API proposal 행 "같은 내용 해시 재요청 0"이 proposal까지 뜻하는지는 아래 사람 결정 1.
- [DECISION] SVG는 **고치지 않고 검사만**(통과 = 원본 인라인, 실패 = 422 `proposal_sheet_rejected`). 04_API 6.2절 "sanitize"를 제거 대신 거부로 해석(저장 객체를 다시 쓰지 않아도 됨). 허용 목록은 packages/drafting SVG 작성기 출력 기준.
- [DECISION] render_ids(렌더 이미지 삽입)는 1단계에서 22023 거부(워커도 `unsupported_render_ids`). renders.output_path 조회·org-files 내려받기·이미지 인라인은 다음 단계.
- [DECISION] 내용 파일 경로는 요청마다 새 uuid(`<org>/arch/proposal_content/<uuid>.json`). 멱등 재전송·start_ai_run 거부 시 고아 파일이 남는다(정리 cron은 사람 결정 4).
- [DECISION] 레이트 리밋 조직 20회/분(04_API에 값 없음, render와 같게, 제안). 본문 상한 512KB(04_API 제안값).
- [DECISION] 재시도: 입력 내려받기·서술 일시 오류·렌더러 오류·120초 렌더 초과·결과 업로드 실패는 재시도 가능(02장 표 "1회(네트워크·타임아웃·429)"), 형식·해시·SVG·숫자 섞인 서술·PDF 아닌 출력은 재시도 없음. 재시도 시 서술을 다시 부른다(서술 비용은 10크레딧에 포함).
- [DECISION] 숫자 포맷: 면적·%는 소수 2자리, mm는 정수, 금액은 정수 원 + 천 단위 쉼표(로캘 무관 자체 구현). 표시 반올림일 뿐 저장 값은 스냅샷 그대로.
- [DECISION] 제안서 전용 오류 3개(`ai_proposal_disabled`·`AI002`·`proposal_sheet_rejected`)는 `gateway/http.ts`(소유 밖)에 없어 proposal 모듈 안에서 같은 봉투로 만든다. 로그는 `{ route:"ai_proposal", code }`만.

## 3. 남은 사람 결정

1. proposal(서술 포함)도 같은 내용 해시 재요청을 0크레딧으로 할지(04_API proposal 행 문구) — 지금 DB는 doc_template만 0. 바꾸려면 마이그레이션.
2. 서술 경로: 국외 상용 LLM vs 오픈소스 강제. `ARCH_PROPOSAL_NARRATIVE_ROUTE` 운영값과 워커 쪽 동의 재확인 위치(실제 서술 연결 시).
3. 공용 WeasyPrint 계약(R-A5) 반영 시점·인증 방식, 120초 타임아웃·글꼴(Noto Sans KR 설치 여부).
4. `proposal_content` 고아 파일 정리 주기(retention cron).
5. 렌더 이미지(render_ids) 삽입 방식: 워커가 renders.output_path를 읽어 data URI로 인라인할지.
6. content 스키마 확정(overview·area_table·cost 필드) — 04_API에 형식이 없어 제안값. 화면(`feat/proposal/**`)과 함께 확정.
7. 꼬리말·도면 고지 문구 최종안(9.1절 도면 고지 원문과 맞추기).
