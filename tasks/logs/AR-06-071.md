## [IMPL] 웹 스튜디오 셸 (2026-11-03, builder)
- 웹 빌드: `apps/desktop` `pnpm build:web`(= `vite build --mode web`) → `build/web`. web mode에서 `@tauri-apps/api*` → `src/web/tauri-stub.ts` alias(결정 9).
  `runtime.ts`·`main.tsx`의 `import.meta.env.MODE === "web"` 분기: `createWebAdapters` 주입(토큰 함수 지연 연결), `webRulePackProvider`(항상 AR063, 결정 11), Fatal 문구, 팝업 콜백 처리. 설치형 번들에는 웹 분기 문자열 0 확인.
- 세션(결정 6): 메모리 Bearer(웹 어댑터 MemorySecureStore 위 supabase 세션). Google = 팝업 + PKCE(`src/web/oauth-popup.ts`): 클릭 직후 빈 팝업 → `signInWithOAuth(skipBrowserRedirect)` URL → `/auth/callback`이 code를 `postMessage(같은 출처)` → opener가 origin·source·형식 검사 후 `exchangeCodeForSession`.
- 호스트(결정 7): `web-hosting.ts`가 env 출처로 CSP 생성·검사(위반이면 빌드 실패) → `build/web-hosting.json`. Vercel은 `vercel.json`이 빌드 전에 읽혀 env 의존 헤더를 못 담으므로 **Build Output API v3**(`VERCEL=1`이면 `.vercel/output/{static,config.json}` 조립)로 낸다. `vercel.json`은 buildCommand(`build:web && check:web`)만. 모든 경로(워커·SPA 폴백 포함) 같은 헤더, `.wasm` application/wasm, `/assets/` 밖만 SPA 폴백.
  CSP: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'; style-src 'self'; img-src 'self' data: blob: <api> <supabase>; font-src 'self'; connect-src 'self' <api> <supabase>; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`.
  COOP/COEP: 안 보냄. SharedArrayBuffer 미사용, COOP same-origin이면 팝업 opener가 끊긴다.
- CORS(결정 8): `apps/web/src/lib/cors/cors.ts` + `proxy.ts`. 허용 = `STUDIO_ORIGIN` + `DESKTOP_CORS_ORIGINS`(https, localhost·tauri.localhost만 http, `*`·null·경로 거부). preflight 204/403, 그 밖 /api 응답에 ACAO(허용 출처만)·`Vary: Origin`·Expose `retry-after`, credentials 없음.
- 무로그인 401(결정 10): `studio-routes.ts` 열거 26건 → 실제 Route Handler를 자식 프로세스(`--conditions=react-server` + `@/` 해석 훅)로 Bearer 없이 호출, 실패 닫힘 스위치 모두 켠 상태에서 24건 401. 클라이언트 `/api` 문자열 스캔이 목록 누락을 막는다.
- 검사: `pnpm check:web` = Tauri IPC 표식 0(대조군 `--expect-tauri dist` 통과) · check-release-bundle · scan-secrets dir · index.html 인라인 0 · 호스트 설정 CSP.

### 사람 확인 (실기 불가)
- WebView2·실제 Vercel 배포: Build Output API를 buildCommand가 낸 `.vercel/output`으로 인식하는지, 응답 헤더(CSP 위반 0)·워커 스크립트 CSP·`.wasm` Content-Type·SPA 폴백.
- 브라우저에서 엔진 워커·manifold WASM 로드(`wasm-unsafe-eval`만으로 충분한지).
- Google 팝업: Google 로그인 페이지 COOP로 opener가 끊기면(`window.opener` null·`popup.closed` 오탐) 로그인 실패. 끊기면 BroadcastChannel 수신으로 바꿀지 팀장 결정.
- Next 실서버에서 proxy 헤더가 Route Handler의 401·500·404·405 응답에 실제로 합쳐지는지(`next start` + curl). 단위 테스트는 proxy 함수·헤더 적용까지.
- DNS(`app.`)·Supabase Redirect URL에 `<스튜디오 출처>/auth/callback` 등록, Vercel env `VITE_*`, web 서버 env `STUDIO_ORIGIN`.
