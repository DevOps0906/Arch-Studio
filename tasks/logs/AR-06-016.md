## [DECISION] Manifold WASM 버전 고정 — 2026-10-29
- `manifold-3d` **3.5.4** 정확 고정(`packages/geometry` dependencies, dist-tag latest = 3.5.4, 2026-09-25 수정). npm tarball 확인:
  LICENSE 파일 Apache-2.0(package.json 메타도 Apache-2.0), sha1 `b5f7b58ded1b3156cafba22ee38ec6173efae860`,
  sha256 `cf57c91fcd33b6315bff28e424ac8c5f04acb5410e9dd8e9886838303910c568`.
- 전이 의존성 35개 전부 MIT·ISC·Apache-2.0 — GPL·AGPL 없음. **예외 확인 필요**: `sharp@0.35.5`(ndarray-pixels ← @gltf-transform/functions)의
  `@img/sharp-*` 네이티브 바이너리가 `Apache-2.0 AND LGPL-3.0-or-later`(libvips). GPL·AGPL은 아니고 apps/web(next)이 이미 sharp 0.34.5를 쓰지만,
  설치형 패키징에 들어가면 LGPL 고지·교체 가능 조건이 붙는다. 엔진은 `manifold-3d` 기본 진입점(manifold.js, import 없음)만 쓰므로 웹 번들에는 안 들어간다.
  `secscan license`는 pnpm lockfile에 라이선스 정보가 없어 판정 0건(정보 없음) → 위 목록은 설치된 package.json·LICENSE 파일로 수동 확인.
- 비동기 초기화: `loadSolidKernel({ locateFile? })` → `Module()` + `setup()`. 엔진 함수(`buildEnvelope`)는 받은 kernel로 동기 실행(모듈 전역 상태 없음).
- 경계 규칙: 입력은 정수 mm(normalizePolygon·정수 검사), 출력 좌표는 `roundHalfAway`. 2D 결과는 `fillPositive`(정수 스냅 라운딩)로 다시 정리,
  3D 메시는 정규화(꼭짓점 사전순·중복 제거, 퇴화 삼각형 제거, 삼각형 정렬). embind 객체는 평가마다 finally에서 delete.
- 주의: 식의 자식 순서가 바뀌면 꼭짓점·부피는 같아도 삼각분할이 다를 수 있다(테스트로 확인) → 엔벨로프는 정규화한 대지 변 순서로 식을 만든다.
  Manifold 메시 출력은 Float32Array — |좌표| ≤ 2^24 mm에서 정수 정확(COORD_LIMIT 1e7 안), 교차점은 float32 오차 후 반올림.

## 구현 요지
- `packages/geometry/src/solid/`: `kernel.ts`(RegionNode·SolidNode 식 평가: polygons/union/intersect/subtract, extrude/hull), `mesh.ts`(canonicalMesh, meshVolume6 bigint 정확 부피).
- `packages/rules/src/envelope/`: `envelope.ts`(buildEnvelope), `params.ts`(일조사선 팩 수치 형식: `bands_by_district`·`road_edges`), `north.ts`(사칙연산 테일러 sin·cos, 90° 배수 정확).
- 제약 상태: applied / reference(지원 지역 밖·조례 미확인, 적용은 함) / unverified·district_not_in_pack·invalid_params·missing(적용 안 함 + `CONSTRAINT_NOT_APPLIED` 경고) / not_applicable.
- 배포 팩 2026.10.0은 전 항목 미확인 → 엔벨로프 = 대지 × 표시 상한, 경고 5건 + `HEIGHT_DISPLAY_CAP`. 법규 수치 0개 추가.
- 산정 가정(팀장 확인 필요): ① `north_angle_deg` = 모델 +Y에서 정북까지 시계 방향 ② 일조 거리는 정북 방향으로 잰 거리, 기준선 = 바깥 법선이 정북 쪽인 대지 변(도로 변은 팩 `road_edges`), 지표면 z=0, 구간 경계 높이는 아래 구간 ③ 이격 = 변별 띠(양끝 d 연장 직사각형) — 오목 꼭짓점은 정사각 캡이라 보수적 ④ 건폐율은 형태가 아닌 바닥 면적 한도(내림) ⑤ 확정 높이 규칙이 없으면 호출자 `cap_height_mm`(법규 수치 아님)로 자름.
- 팩 형식: `pack.ts`의 sunlight params는 `record<unknown>`이라 엔벨로프가 따로 검사한다(형식이 다르면 invalid_params). 로더에서 검사하려면 pack.ts 수정 필요(범위 밖).

## 리뷰 반영 (2026-10-29, ACCEPT 🟡 4건)
1. 정수화 퇴화: `closeMesh`(solid/mesh.ts) — 면적 0 삼각형 제거 + 긴 변 맞은편 삼각형을 가운데 꼭짓점에서 분할(T자 접합 메움), 방향 반대 중복 면 쌍 제거,
   닫힘 재검사 실패 시 `SolidError("SOLID_DEGENERATE")`(geometry errors.ts는 범위 밖이라 solid/errors.ts에 별도 클래스).
   닫힘 정의는 "변마다 (a,b) 개수 = (b,a) 개수". 진단 결과 벤치 120건 중 4건이 Manifold가 서로 다른 꼭짓점으로 둔 "모서리로 맞닿은 두 솔리드"
   (지면 영역이 한 점에서 맞닿아 압출된 경우, float 좌표 완전히 같음)라 정수 좌표로 합치면 한 변에 네 면이 붙는다 — 기하는 닫혀 있어 허용(팀장 확인 필요: "정확히 2면" 엄격 정의와 다름).
   회귀 테스트: 정수 사면체 × 1mm 상자 재현 사례 + 무작위 600건(항상 닫힘·면적 0 없음), 일직선 삼각형 수리, 열린 메시 → SOLID_DEGENERATE.
2. 부피 bigint: `meshVolume` → bigint, `volumeToString`; `EnvelopeOutput.volume_mm3: bigint`, `serializeEnvelope`(정규 JSON, 부피 10진 문자열). 1km×1km×30m = 3e16 테스트.
3. 좌표 한계: 클리핑 대신 **대지 경계 상자 중심을 원점으로 옮긴 국소 좌표**에서 계산 후 정수 이동으로 되돌림(팀장 지시와 방법 다름 — 이격 띠뿐 아니라
   일조 쓸기·쐐기 볼록 껍질까지 한 번에 한계 안에 들고, 클리핑 반올림 변형이 없다). x = 10,000,000에 붙은 대지 = 원점 대지 + 이동과 꼭짓점·부피 동일 테스트.
4. 독립 검증: 가짜 신 기준 구간 경계 단면(z 0·4000·7000·12000의 y 한계 13800·12000·10333·7000, x 1000~19000), 정북 30° 방향별 제한점(±1mm:
   z 3000에서 x 18500·y 12402, 아래 구간 19000·14000, 꼭대기 x 14000·y 4608) 손계산 단언.
- 골든 변경 이유: ① 4케이스 모두 `volume_mm3`가 숫자 → 10진 문자열(bigint 직렬화) ② fixture-north-30deg 삼각형 목록만 변경(국소 좌표 이동으로 Manifold 삼각분할이 달라짐, 꼭짓점·부피 동일).
- 벤치 재측정(국소 좌표·closeMesh 포함, n=50): 구 기준 p95 298.6ms, 신 기준 p95 232.1ms.
