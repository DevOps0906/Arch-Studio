# AR-06-029 DXF 가져오기 파서 (2026-10-29)

`packages/io/src/dxf-import/**`. 진입점 `importDxf(bytes | string, options) → DxfImportResult`. DesignModel은 만들지도 고치지도 않는다(후보 타입만).

## 결과 형식 (035 대지 화면이 쓸 것)
- `{ ok:true, status:"ok", unit, candidates[], warnings[], stats }` — 후보는 순위순(최대 10, 옵션 1~50). `unit.needs_confirmation`이 true면(범위 추정) 단위 확인 대화상자를 반드시 보인다. `warnings[0].code==="AR054"`면 `skipped_entities`(종류→개수)를 표시한다.
- `{ ok:true, status:"needs_unit", code:"AR053", reason, declared_insunits, options:[{unit, plausible, reference_extent_mm, fits_coord_limit}] }` — 후보 없음. 사용자가 고른 단위를 `options.unit`으로 넘겨 다시 호출.
- `{ ok:false, error:{ code, message, line?, limit? } }` — 코드: `AR055`(크기), `DXF_BINARY`, `DXF_MALFORMED`, `DXF_TRUNCATED`, `DXF_EMPTY`, `DXF_TOO_MANY_ENTITIES`, `DXF_NESTING_TOO_DEEP`, `DXF_CIRCULAR_BLOCK`, `DXF_COORD_OUT_OF_RANGE`, `DXF_INVALID_OPTION`, `DXF_INTERNAL`(버그, 퍼징 0건).
- 후보: `{ rank, polygon{outer(반시계, 사전순 최소 꼭짓점 시작), holes:[]}, area_mm2, perimeter_mm, vertex_count, layer, layers, layer_hint, source }`.

## 결정·문서와 다른 점
1. **단위 집합**: 04_API는 `'mm'|'m'`. 여기서는 `mm|cm|m|in|ft`(헤더 $INSUNITS 1·2·4·5·6 선언 대응). 자동 추정은 mm·m만(두 범위가 겹치지 않음: 대지 최대 변 3m~1km). cm·in·ft는 선언되었거나 사용자가 고를 때만. 04_API `import_dxf` 결과 형식은 `status` 분기형으로 확장 제안(`ask_unit` 배열 → `needs_unit.options`).
2. **조용한 추정 금지의 해석**: 헤더 선언이 도형 크기와 맞으면 선언 사용(확인 불필요). 선언 없음·0·모순이면 mm/m 중 하나만 그럴듯할 때 `range_heuristic` + `needs_confirmation:true`, 아니면 AR053. 이 해석이 PRD :379와 맞는지 팀장 확인 요청.
3. **파싱 오류 코드**: 04_API 7.3에 가져오기 파싱 실패 코드가 없어 `DXF_*` 문자열을 썼다. `AR062` 등으로 정식화 제안(화면 문구는 03장 2.4절 "이 파일에서 도면 요소를 읽지 못했습니다" 하나로 매핑 가능).
4. **Node 내장 금지·TextDecoder 타입 없음**으로 UTF-8 디코더 자체 구현. CP949 도면은 한글 레이어 이름만 깨진다(좌표 무관). 레이어 힌트의 한글 규칙은 UTF-8 도면에서만 동작.
5. 삼각함수는 `Math.sin/cos` 대신 사칙연산 테일러(`trig.ts`), 불룩 호는 이등분 재귀(제곱근만) — geometry와 같은 "초월함수 금지" 원칙.
6. `packages/io/tsconfig.json`을 geometry와 같게 만들었다(`allowImportingTsExtensions`, 테스트·bench 제외). 소유 경계 밖이지만 `.ts` import에 필수. `pnpm-lock.yaml`은 workspace 의존성(domain·geometry) 추가분만 변경.

## 동작 요약
- 지원: LINE·LWPOLYLINE(bulge)·POLYLINE+VERTEX·ARC·CIRCLE·INSERT(회전·배율·음수 배율·MINSERT 배열·블록 기준점·0 레이어 상속), 압출 -Z(x 반전). TEXT/MTEXT/ATTRIB/ATTDEF는 경고 없이 무시(`ignored_annotations`). 그 밖은 AR054(곡선맞춤/메시 POLYLINE 포함). 배치 공간(67=1)·꺼짐/동결 레이어는 무시(통계만).
- 루프: 닫힌 폴리라인·원은 바로, 열린 선/호는 끝점(허용 1mm, 옵션 0)으로 이어 "모든 끝점 차수 2"인 단순 고리만. 갈라지는 점이 있으면 만들지 않는다(모호). 1㎡ 미만·꼭짓점 2000 초과·자기교차는 제외(통계), 같은 모양은 합침. 순위: 레이어 힌트(site>neutral>non_site) → 면적 → 최소 꼭짓점 → 입력 순서.
- 상한: 20MB(AR055), 엔티티 50만, 펼친 엔티티 100만, 꼭짓점 400만, INSERT 깊이 8(초과·순환은 오류), MINSERT 1만, 좌표 ±10km. 상한 초과는 부분 결과 없이 오류. 호출자는 상한을 낮출 수만 있다.
- 알려진 한계: 홀(구멍)·면 분할(평면 그래프 면 추적)은 하지 않음, 타원·SPLINE·HATCH 경계는 미지원(AR054), 압출이 ±Z 외인 OCS 미지원, 배치 공간 뷰포트 변환 미지원.

## 테스트·성능
- `pnpm --filter @arch-studio/io test`: 단위 23 + 라운드트립(작성기 골든 writer-* 전부 + 요약) + 퍼징 7,800건(임의 바이트 2,000 · 바이트 변조 2,500 · 줄 변조 1,500 · 골든 변조 300 · 숫자 자리 변조 1,500; 시드 고정). 예외 0, `DXF_INTERNAL` 0.
- 성능(`node --expose-gc packages/io/src/dxf-import/bench.ts <mixed|rects|lines|poly>`, Intel Xeon 2.1GHz 4코어, Node 22, 20MB 합성): mixed 1.37초(엔티티 17.2만, heap +143MB), rects 1.64초(14.7만 닫힌 도형, heap +158MB), lines 1.45초(24만 선분·끝점 그래프, heap +164MB), poly 0.85초(꼭짓점 304만, heap +71MB). 프로세스 최대 RSS 약 280~310MB(입력 바이트·문자열 포함). 개발서 12.8절 예산(DXF 가져오기 항목 없음)과 무관하게 20MB가 2초 안쪽.
