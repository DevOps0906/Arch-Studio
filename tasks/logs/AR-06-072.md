# AR-06-072 로그 — 웹 어댑터(ProjectStore 클라우드+IndexedDB 읽기 캐시, FileGateway, SecureStore, EntitlementClient, Updater 없음)

## 구조 (2026-11-02)
- `packages/shell-bridge/src/web/`
  - `adapters.ts` `createWebAdapters(options)`: capabilities = `WEB_CAPABILITIES`, `updater: null`, `entitlement.license: null`, rasterizer 없음. `clearSecrets()` = 비밀 전부 + 읽기 캐시 `clear()` + 권한 판정 초기화(하나가 실패해도 나머지 수행 후 첫 오류).
  - `http.ts` `WebHttp`: 같은 출처 `/api/*`(봉투 `{ok,data}`/`{ok:false,error:{code}}`, status·code만 읽음), Bearer = 메모리 SecureStore의 supabase 세션 `access_token`(기본, 주입 가능). Storage 서명 URL은 인증·쿠키 없이(`credentials: "omit"`).
  - `project-store.ts` `WebProjectStore`: 저장 = `POST /api/cloud-projects/{id}/upload-url`(ext arch, bytes, sha256) → 서명 URL PUT → `POST /api/cloud-projects`(expected_version: null→0). 열기 = `GET /api/cloud-projects/{id}/blob` → 캐시 version 같으면 캐시, 아니면 내려받아 sha256·형식 검증 후 캐시. 삭제 = `DELETE /api/cloud-projects/{id}?expected_version=N`(제안 라우트). 목록 = 커서 끝까지(최대 200쪽).
  - 상태 매핑: 409/`AR041` → VERSION_CONFLICT, 404 → NOT_FOUND, 402(web_edit 없음) → AR061(읽기 전용), 422 → INVALID_INPUT, 그 밖·네트워크 → PROJECT_UNAVAILABLE.
  - `project-cache.ts` `ProjectReadCache` + `IdbProjectCache(IDBFactory)`(DB `arch-studio-read-cache`, store `projects`). 캐시 실패는 삼키고 로그아웃 `clear()` 실패만 알림.
  - `file-gateway.ts` `WebFileGateway(host)` + `browserFileHost()`(File System Access API → `<input type=file>`·다운로드 Blob). 순서: 확장자 → `assertImportSize(kind, File.size)` → `arrayBuffer()` → 길이 재확인. 저장 결과 `pathHash = sha256("web:" + 파일 이름)`.
  - `entitlement.ts` `WebEntitlementClient`: `GET /api/entitlement` 세션당 1회(실패는 기억 안 함). rights[f] true → Allow, false → 사유(좌석 revoked/unassigned → `licensed_fallback` → expired → no_product), 서버 rights에 없는 키(ai_chat) → unverified, 네트워크 실패 → offline. view_export 항상 Allow.
- 루트 `index.ts`에 `createWebAdapters`·`IdbProjectCache`·`browserFileHost`·`WebEntitlementClient`와 타입 export 추가.

## 결정
- **읽기 캐시만**: `save`는 캐시를 읽지 않는다(createdAt은 이번 세션에 열어 둔 값 → 없으면 서버에서 `open`). 캐시에 넣는 것은 서버에서 받은 리비전, 또는 서버가 방금 받아들인 리비전뿐. 테스트가 캐시 호출 순서(`["put"]`)와 업로드 바이트에 캐시 내용이 없음을 확인.
- **IndexedDB 팩토리는 주입**: `no-web-storage.test.ts`가 shell-bridge 소스의 `indexedDB` 문자열을 금지하므로 웹 전역을 직접 읽지 않는다. 앱 조립부가 `createWebAdapters({ idb: <브라우저 팩토리> })`로 넘긴다. 넘기지 않으면 캐시 없이 서버만.
- **스냅숏(.arch) 형식**(제안): UTF-8 JSON `{ format: "arch-studio.project", formatVersion: 1, project: { id, name, siteLabel, clientName, clientContact, createdAt, updatedAt, schemaVersion, engineVersion, note, designModel, sha256 } }`. version은 서버 행이 정본이라 넣지 않음.
- **SecureStore** = `MemorySecureStore`. httpOnly 쿠키는 서버(@supabase/ssr) 몫이라 JS가 다루지 않는다. 현재 cloud API는 Bearer만 보므로 쿠키 기반 CSRF 면 없음.

## createPlatformAdapters 웹 기본값 교체 — 보류(팀장 확인 필요)
- `apps/desktop/src/shell/runtime.ts`가 Tauri 웹뷰 밖에서 `NOT_SUPPORTED`를 받아 안내 화면을 띄운다. 기본값을 웹 어댑터로 바꾸면 이 동작이 깨진다. 또 `bridge.ts`·`tauri/adapters.test.ts`는 이번 쓰기 허용 밖.
- 제안: 기본값은 그대로 두고 apps/web 조립부가 `createPlatformAdapters({ web: () => createWebAdapters({ idb }) })`를 부른다.

## 서버 라우트 제안 (apps/web/src/server/** 금지라 구현 안 함)
1. `GET /api/cloud-projects/{project_uuid}/blob`(04_API 62행, 072 소유): `{ url(https 서명 10분), version, bytes, sha256?, schema_version }`, entitled=false 허용, 없으면 404.
2. `DELETE /api/cloud-projects/{project_uuid}?expected_version=N`(04_API에 없음): 소프트 삭제, 불일치 409 `AR041`, 없음·삭제됨 404. 삭제된 id로 다시 저장하면 404(ProjectStore 계약).
3. `POST /api/cloud-projects`에서 행이 없는데 `expected_version ≥ 1`이면 404(계약상 NOT_FOUND). 현재 RPC 설명은 AR041만 언급.
4. `GET /api/entitlement` 라우트 없음(074).

## 발견한 문제
- 이름 한도 불일치: ProjectStore 200자(Rust 동일) vs cloud API·DB 120자. 계약 하네스의 200자 케이스는 가짜 서버가 받아 통과하지만 실서버는 422 → INVALID_INPUT.
- ProjectErrorCode에 AR040(사본 개수 한도)·AR031(크기)이 없어 PROJECT_UNAVAILABLE로 뭉개진다. 화면 문구가 필요하면 `adapters/errors.ts`에 코드 추가 필요.
- 목록 API에 siteLabel이 없어 웹 목록의 `siteLabel`은 항상 null.
- `browserFileHost`(DOM 경로)는 Node 테스트에서 돌지 않는다(실브라우저 확인 필요).
