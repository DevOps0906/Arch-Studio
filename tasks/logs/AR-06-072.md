## 구현 (2026-11-02)
- `adapters.ts` createWebAdapters({baseUrl, getAccessToken, fetch?, fileHost?, cache?}). 비밀 = MemorySecureStore(D-071a: Bearer, 쿠키·localStorage·sessionStorage 0). OAuth 복귀 방식은 가정하지 않음(토큰은 주입 함수로만 받는다).
- `project-store.ts` 저장 = 사전 확인(GET blob 메타) → POST /{id}/upload-url → PUT 서명 URL → POST /api/cloud-projects. 열기 = GET /{id}/blob → 서명 URL. blob(.arch) = JSON(kind arch-cloud-project v1, 전체 이름·대지·고객·designModel 문자열). AR041 409 → VERSION_CONFLICT.
- `read-cache.ts` IndexedDB 읽기 캐시(list·open 결과만). 서버 미도달(네트워크·5xx)일 때만 되돌려줌, save/delete는 캐시를 읽지 않음. clearSecrets가 비밀+캐시 삭제(캐시 삭제 실패는 던짐).
- `file-gateway.ts` input[type=file] / showSaveFilePicker / 다운로드 Blob. File.size로 assertImportSize 후에만 arrayBuffer. `entitlement.ts` GET /api/entitlement rights·seat·products 매핑, 실패 닫힘. updater = null.
- no-web-storage 테스트: indexedDB 참조는 web/read-cache.ts 한 곳만 허용으로 좁힘. bridge.ts 주석 갱신.

## 결정·차이 (팀장 확인 필요)
1. 서버가 하드 삭제 → "삭제 후 재저장 NOT_FOUND"는 인스턴스 메모리 묘비로만 보장(계약 통과용).
2. 서버 name 1..120자 → 목록 name은 잘라서 보냄(전체 이름은 blob). 목록에 siteLabel 없음 → 같은 버전을 읽은 적 있으면 그 값, 아니면 null.
3. 오류 코드: 402/AR040/AR031은 ProjectErrorCode에 없어 PROJECT_UNAVAILABLE(413·422는 INVALID_INPUT). 화면이 구분하려면 errors.ts에 코드 추가 필요(072 쓰기 범위 밖).
4. 서버에 `GET /api/cloud-projects/{id}/blob`·`GET /api/entitlement` 라우트가 아직 없음(apps/web). 04_API 계약대로 호출하며 테스트는 가짜 서버. 서버 구현 필요.
5. createPlatformAdapters 웹 기본값은 교체하지 않음: 웹은 baseUrl·토큰 주입이 필요해 `web: () => createWebAdapters(...)` 주입 유지.
6. 저장 때 createdAt 유지를 위해 이 인스턴스가 못 읽은 프로젝트는 blob을 한 번 내려받음(서버 목록에 created_at 노출 시 제거 가능).
7. 캐시 IndexedDB는 사용자별 분리 없음(로그아웃에서 비움).
