# AR-06-054 법규 질의 채팅(arch.chat)

## [DECISION] 착수 전 (2026-11-02, 팀장 — 사용자 방침 "막히면 기록하고 계속") — challenger REVISE(🔴3 🟠3 🟡4) 반영
1. **이번 범위는 Dify를 핵심 경로에서 뺀다**: web POST /api/ai/chat → (세션·자격·차감) → FastAPI `/tools/answer`(=answer-direct)를 **web이 서명한 EdDSA 토큰(scope=chat, org·conv·request 클레임, 기존 ai-token 서명기·JWKS 재사용)**으로 직접 호출. FastAPI는 DB 없이 토큰 클레임의 org만 쓴다(🔴1 해소). `infra/dify/arch-chat/` DSL은 저장소에만 두고 연결은 후속 — 연결 전 결정: Dify 로그 30일 보존·처리위탁 고지(AI_ARCHITECTURE.md:69), DSL "HTTP 노드 answer 원문만, 뒤 LLM 노드 0·공급자 /v1/chat/completions 고정" 검사(049 우회 방지). 04_API·AI_ARCHITECTURE 정정 필요.
2. 멱등(🔴2): 계약에 클라이언트 `request_id`(UUID v4) 필수, 키 `chat:<org>:<request_id>`. 턴 번호 n은 키에 쓰지 않음. 첫 턴 재시도도 같은 request_id면 대화 1개·차감 1회(conversation 생성도 request_id로 멱등). 중복이면 저장된 답변 재전송(ai_messages에 저장되므로 053과 달리 재생 가능), 처리 중이면 409.
3. 출처 보장(🔴3): FastAPI가 구조화 답변 {sentences[{text, source_ids}], sources, no_source}을 끝까지 만든 뒤 web이 소속 재검사(출처 없는 문장 제거, 0문장 → no_source) **후** SSE로 문장 단위 송출(버퍼링 후 송출). 부분 스트림 실패 개념 없음.
4. 과금(🟠1·🟠3): 턴 1크레딧(answer-direct 포함). 답변이 클라이언트로 송출 시작되기 전 실패·타임아웃(전체 60초 제안) → 전액 환불. 송출 시작 후 클라이언트 중단은 차감 유지. no_source("근거를 찾지 못했습니다")는 **환불**(제안). "폴백 상태 턴 0" = 라이선스 폴백(ai_chat=false) → 403, Dify 장애와 무관.
5. 일일 턴 상한(🟠2): DB 원자 집행은 마이그레이션 필요 → 이번엔 원장 오늘(KST) 건수 조회로 근사 검사(동시 요청 시 소폭 초과 가능), 원자 카운터 마이그레이션은 운영 전 차단 후속.
6. 🟡: start-run.test.ts 허용 목록에 server/ai/chat 명시. application_date 기본 오늘 KST(선택 인자로 프로젝트 적용일). 숫자는 인용 청크 원문에 그대로 있는 숫자만 허용(엔진 값 없음). 메모리 레이트리밋·jti는 기존 운영 전 차단과 동일.
7. 킬 스위치 `ARCH_AI_CHAT_ENABLED` 기본 off. 실제 LLM 미연결(가짜). 대화·메시지는 core.ai_conversations/ai_messages에 web(service_role)이 저장(테이블 기존, 마이그레이션 없음 — 칼럼 부족 시 기록만).
8. 순서: (A) api /tools/answer + (B) web 라우트·토큰·저장·SSE 병렬, 위험 높음 → reviewer(code)+reviewer(security).
