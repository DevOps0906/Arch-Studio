3. 출처 보장(🔴3): FastAPI가 구조화 답변 {sentences[{text, source_ids}], sources, no_source}을 끝까지 만든 뒤 web이 소속 재검사(출처 없는 문장 제거, 0문장 → no_source) **후** SSE로 문장 단위 송출(버퍼링 후 송출). 부분 스트림 실패 개념 없음.
4. 과금(🟠1·🟠3): 턴 1크레딧(answer-direct 포함). 답변이 클라이언트로 송출 시작되기 전 실패·타임아웃(전체 60초 제안) → 전액 환불. 송출 시작 후 클라이언트 중단은 차감 유지. no_source("근거를 찾지 못했습니다")는 **환불**(제안). "폴백 상태 턴 0" = 라이선스 폴백(ai_chat=false) → 403, Dify 장애와 무관.
5. 일일 턴 상한(🟠2): DB 원자 집행은 마이그레이션 필요 → 이번엔 원장 오늘(KST) 건수 조회로 근사 검사(동시 요청 시 소폭 초과 가능), 원자 카운터 마이그레이션은 운영 전 차단 후속.

7. 킬 스위치 `ARCH_AI_CHAT_ENABLED` 기본 off. 실제 LLM 미연결(가짜). 대화·메시지는 core.ai_conversations/ai_messages에 web(service_role)이 저장(테이블 기존, 마이그레이션 없음 — 칼럼 부족 시 기록만).

## [A] /tools/answer (api) — 구현 완료
- 계약: POST /tools/answer, Bearer 사용자 토큰 scope=chat(잡 토큰·다른 scope 403), 본문 strict(org 등 추가 키 422), jti 1회 소비.
  응답은 기존 봉투 `{ok:true,data:{answer:{sentences[{text,source_ids}]},sources[{chunk_id,title,article,effective_from}],no_source}}`. LLM/검색 실패 502 PROVIDER, 미구성 503.
- 처리: search_effective(k=5, 토큰 org) → 청크 0이면 LLM 없이 no_source → StructuredLLM → 지어낸 id 제거 → 인용 청크 밖 숫자 문장 1회 재작성 후 제거 → compliance WARN·FAIL 문장 제거(채팅엔 "확인 필요" 칸이 없어 WARN도 제거) → 0문장이면 no_source=true.
- 고정 문구 "근거를 찾지 못했습니다"는 answer.NO_SOURCE_TEXT 상수; 응답엔 넣지 않고 web이 표시.
- article은 청크 metadata.article, 없으면 title로 대체. 코퍼스·LLM은 주입(create_app(chat=ChatDeps)); 미주입이면 503.
- 파일: app/ai/tools/arch/answer.py, app/routes/tools.py, schema.py(Chat*), tests/arch/test_tools_answer.py.
