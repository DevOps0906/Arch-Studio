# AR-06-054 Dify `arch-chat` + `/tools/answer`(+answer-direct) + `POST /api/ai/chat` 중계

근거: 06_AGENT_PLAN.md AR-06-054 행, 01_PRD.md AR-F-009·4.5·4.9절, 02_ARCHITECTURE.md 5장 `arch.chat` 행·환경 변수 표, 04_API.md 1장(선차감 위치)·2.2절 `/api/ai/chat` 행·6.3·6.4절·12장 Dify 행.

## 구현
- `apps/api/app/ai/tools/arch/**`(+ `app/ai/tools/__init__.py`, `app/main.py` 라우터 등록 2줄: import·include)
  - `answer.py` 본체: 시행 중 지식 검색(`KnowledgeIndex.search` 모양, 기준일 = 오늘 KST, 전국 공통만) → 결과 0이면 LLM 미호출 no_source
    → LLM(`AnswerGenerator`, feature `arch.chat`, 입력은 질문·근거 조각만, org는 라우팅용) → 인용 id 중 검색 결과에 있는 것만 출처 → 0개면 문장 폐기·no_source.
    출처 메타(law=제목, article=청크 첫 줄 "제N조(의M)", effective_from, source_id)는 서버가 청크에서 만든다.
  - `POST /tools/answer`: 내부 키 미설정 503 → `X-Internal-Key` 상수 시간 비교 401 → strict 본문 422(org·토큰 키 거부) → (대화 id, dify_user) 매핑 불일치 404 → 답.
  - `POST /tools/answer-direct`: 서명 토큰 401 → 사용자 토큰만·scope `chat` 403 → strict 본문 → `conv` 바인딩 403 → jti 1회 401 → 답(org = 토큰).
  - 의존성은 `app.state.arch_chat`(`ChatTools`). 기본값은 전부 미설정 → 503(실패 닫힘). 운영 배선(DB 대화 매핑·DB 색인·라우터 LLM)은 이 작업 밖.
- `apps/web/src/server/ai/chat/**`, `apps/web/src/app/api/ai/chat/route.ts`
  - 순서: 설정 없음 503(인증 전) → 인증 → 사용자 20회/60초 → member+ → 엔타이틀먼트 → strict 본문 `{ request_id, conversation_id?, message 1..2000 }`
    → 일일 상한(`ai_chat_turns_per_day`, 0·없음 = 폴백 상태 포함 429 `AI_DAILY_LIMIT`, 오늘 KST 0시 이후 chat 차감 원장 수) → 대화 확인(본인·active, 아니면 404)
    → 선차감 1 `chat:<org_id>:<request_id>` + 원장 nonce·조직·행위자·금액·대화 대조(아니면 409 `chat_request_done`, 053 결함 반복 방지)
    → 새 대화 생성(service_role) → Dify(실패 시 `ai_chat.dify_unavailable` alert 로그 + answer-direct) → 출처 재검사 → 확정/환불 → SSE.
  - Dify 장애 판정: 연결 실패·비 2xx·조각 간 10초 무응답·error 이벤트·계약 위반·60초 총 상한.
  - Dify 요청: `inputs`는 `platform_conversation_id`만, `user` = `du_` + HMAC(DIFY_USER_HMAC_SECRET, org·user) 32자. 토큰·org·user id 0(테스트로 확인).
  - SSE: `delta {text}` → `citations {citations}` → (`no_source {message}`) → `done {conversation_id, request_id, credits, fallback}`. 출처 검사를 위해 상류 답 전체를 받은 뒤 보낸다.
- `infra/dify/arch-chat/README.md`: Chatflow(시작 → HTTP `/tools/answer` → 답변 = 응답 본문 그대로) 설정. DSL은 Dify에서 만든 뒤 내보내 커밋(노드 문법 미확인이라 손으로 쓰지 않음).

## 크레딧(0크레딧 여부) — 3차 정정(리뷰 🔴: "폴백 상태 턴 0" = 라이선스 폴백 조직의 일일 턴 0)
| 결과 | 크레딧 |
|---|---|
| 출처 ≥1(Dify 또는 Dify 런타임 장애 시 answer-direct 폴백) | 1 |
| 출처 없음("근거를 찾지 못했습니다") | **0**(환불 `chat_no_source`, 04_API "제안") |
| FastAPI 거절 4xx(예: 질문 따옴표·줄바꿈으로 본문 JSON 깨짐 422) | 0(환불 `chat_rejected`, 폴백 없음, 422 `invalid_input` 또는 503) |
| Dify·폴백 모두 장애 | 0(환불 `chat_failed` + 503 `AI_UNAVAILABLE`) |
| 확정 직전 클라이언트 중단(req.signal.aborted) | 0(환불 `chat_aborted`, 499) |
| 설정 누락·일일 상한(라이선스 폴백 상태 0 포함)·입력·권한·대화 404·CR001 | 차감 전 거부(0) |
- 환불 실패는 `ai_chat.refund_failed`(alert) 로그만 남기고 답이 있으면 그대로 전달(done.credits = 실제 차감).
- 상류 상한: Dify 총 45초(조각 간 10초) + direct 25초 = 70초, route `maxDuration = 120`.
