## 결정
- **005 `NativeBridge.capabilities`는 4키 그대로.** 005 테스트가 웹 capabilities를 4키 deepEqual로 검사하고 008이 이 모양을 쓰므로, 확장 키는 `PlatformAdapters.capabilities`(`PlatformCapabilities`)에만 둔다. 값은 한 곳(`adapters/capabilities.ts`)에서 정의하고 NativeBridge는 4키 사본(`bridgeCapabilities`)을 쓴다.
- **capabilities = "이 빌드에 구현이 있는가".** 설치형 `autoUpdate=false`(updater 작업 전), `licenseActivation=false`(041 전). 불변식 `updater !== null ⇔ autoUpdate`, `entitlement.license !== null ⇔ licenseActivation`을 계약이 검사.
- **설치형 EntitlementClient는 실패 닫힘.** 근거(041 라이선스 파일·074 서버 판정)가 없으므로 `view_export`만 Allow, 나머지 `Deny("unverified")`. 화면이 아직 이 판정을 쓰지 않아 영향 없음. 041·074가 근거를 넣는다.
- **취소 표현**: Rust `export_save_file`은 취소를 `Ok(None)`으로 주지만 005 Exporter 계약대로 `BridgeError("CANCELLED")`로 바꾼다(가져오기도 CANCELLED 오류).
- **오류 detail 폐기**: Rust `VERSION_CONFLICT` detail(현재 version)·`AR055` detail(상한)·io 종류 모두 버리고 코드만. 어댑터마다 알려진 코드 목록만 통과(다른 어댑터 코드는 대체 코드로).
- **입력 검사 중복**: TS가 invoke 전에 Rust와 같은 한도로 검사(id UUIDv7, 이름 200자, 텍스트 1000자, engineVersion 64B, designModel 64MiB·`{` 시작, expectedVersion ≥1). 값이 IPC·오류 경로로 가지 않게 하고 웹 구현과 같은 규칙을 공유. JSON 객체 여부 최종 판정은 저장소(Rust·서버).
- **하네스 위치**: `testing/contract.ts`(`./testing` 하위 경로). `test-helpers.ts`는 testDouble 린트상 비테스트 파일에서 import할 수 없어 누출 검사 함수(`surface`)를 하네스 안에 따로 둠(5줄 중복).
- **`InvokeFn` 인자 타입 확장**: `args: Record<string, unknown> | Uint8Array`, 셋째 인자 `options?`. 패키지 밖 구현자 0(검색 확인). 이름은 유지.
