## 계약 반영 (팀장 확정 ①~④)
- ① `MM_COORD_LIMIT = 10_000_000`(domain `units.ts`), `mmSchema` = int + ±상한(safe int 자동). `polygonSchema` 외곽·구멍 `.min(3)`. geometry `normalizePolygon`이 범위 밖·면적 0·자기교차·구멍 위치를 `GeometryError.code`로 거부하고 방향(외곽 반시계·구멍 시계)을 정리. 방향을 뒤집으면 꼭짓점 순서가 `[p0, p(n-1), …, p1]`(변 번호가 바뀜 — `roads.edge_index` 쓰는 쪽 주의).
- ② `distance(a, b)` → `{ d2_mm2, d_mm, pair, d2_exact: { num, den } }`, `compareDistance(result, limit_mm)`은 bigint 정확 비교. **계약 차이(팀장 확인 필요)**: 최근접점이 변 내부면 정확한 제곱 거리는 정수가 아니다(유리수). 그래서 `d2_mm2`는 정확값을 half-away 반올림한 정수이고, 정확값은 `d2_exact`에 따로 담았다(bigint라 JSON 직렬화 불가 — 저장은 d_mm·d2_mm2만).
- ③ `union(polygons)`, `offset(polygon, delta_mm, { join: "miter" | "square", miterLimit = 2 })` → `Polygon[]`(빈 배열 허용). 결과는 일직선 꼭짓점 제거, 사전순 최소 꼭짓점 시작, 다각형·구멍 정렬, `holes` 항상 배열, 결과 좌표 ±10km 초과 시 `OUT_OF_RANGE`.
- ④ `roundHalfAway`·`roundRatioHalfAway`는 `geometry/src/round.ts` 한 곳. domain `mToMm`은 최단 10진 표기(String, 명세 고정) 자릿수 이동 방식으로 고침(0.5005 m → 501 mm; 기존 `Math.round(m*1000)`은 500).

## [FIX] 오프셋 바늘 꼭짓점 결함 — 2026-10-29
- 증상: `offset({outer:[[0,1],[-1,24],[-1,0]]}, -24)`(폭 ~1mm 삼각형)이 원본 밖 다각형 `[[-24,-1],[-1,0],[-2,1],[-24,0]]`을 반환(miter·square 둘 다). 속성 테스트 seed -1130307967에서 간헐 실패.
- 원인: 오목(겹치는 쪽) 판정 `cosA > -0.999 && sinA·δ < 0`이 Clipper2를 따라 법선 cos ≤ -0.999(꼭짓점 각 약 2.6° 이하, 바늘 끝)를 오목에서 뺐다. 그런 꼭짓점이 안쪽 오프셋의 겹치는 쪽이면 세 점 삽입 대신 square/miter 마개가 붙어, 원본 밖으로 뻗은 감김수 +1 영역이 positive 정리에서 살아남았다.
- 수정: 오목 판정을 정수 외적 `sign(orient(이전, 현재, 다음))·sign(δ) < 0` 하나로(예외 없음, 부동소수 부호 대신 정확). 원시 경로 사슬 = ∂P + (sign δ)·Σ∂(변 띠·벌어지는 쪽 모서리 조각)이 되어 감김수 > 0 이 P ∪ 조각(δ>0) / P \ 조각(δ<0)과 같다 → 안쪽 결과 ⊆ 원본. 구멍 쪽(바깥 오프셋에서 바늘 구멍)도 같이 고쳐진다.
