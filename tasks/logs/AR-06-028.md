# AR-06-028 로그 — 매스 자동 제안 3안 + 모델러 제안 패널

## 구현 요지
- `packages/massing/src/{suggest,grid}.ts`: `suggestMasses(model, pack, kernel, targets)` 결정적 순수 함수(난수·시간·LLM 없음).
  1. `rules.buildEnvelope` 지면 영역 → 격자(축당 ≤48칸) 칸 판정(정수 정확) → 직사각형 열거 → 네 변을 100mm 단위까지 밀어 정확 다듬기.
  2. 후보마다 "엔벨로프 안 최대 층 수"를 커널 솔리드 차집합 이진 탐색(넘침 ≤ 1,000,000mm³ = 부동소수 조각 허용)으로 구하고, 원하는 층수가 안 들어가면 정북 쪽 변을 100mm 단위로 물려 맞춘다. 건폐율 한도(`max_building_area_mm2`)는 긴 변을 잘라 맞춘다(부분집합이라 층 수 유지).
  3. 전략: 건폐 최대(바닥 면적 최대) · 일조 여유(정북 쪽 2,000mm 더 물림, 엔벨로프 허용 층 대비 여유 층 비율 최대) · 정형 평면(긴 변 ≤ 짧은 변 1.5/1.2/1.0배, 두 변 1,000mm 배수). 서로 같은 바닥·층이면 다음 후보로 넘겨 3안이 서로 다르게 한다.
  4. 마지막에 `rules.judge`를 실제로 돌려 FAIL이 있으면 층을 줄이거나 바닥을 100mm씩 물리고, 못 고치면 버린다 → **후보는 FAIL 0**(테스트: 판정 엔진 재실행 + 독립 솔리드 검사).
- 목표 미달: `notices[TARGET_NOT_MET]` "엔벨로프 안에서 최대 <값>㎡입니다." + `max_gfa_m2` + FAIL 없는 후보 그대로. 엔벨로프가 비면 ENVELOPE_EMPTY, 최소 변(3,000mm) 미달이면 NO_CANDIDATE.
- `apps/desktop/src/workers/suggest.handlers.ts`: 기존 `suggest_mass` op(suggest 레인, 최신만 유효)를 채움. zod로 모델·목표 검사, 규칙 팩 선택, 커널은 `engine.worker.ts`에서 모델러 핸들러와 **하나를 공유**. 응답에 후보별 `judge`({result, details, warnings})를 동봉.

## 문서와 다르게 한 점 / 가정 (팀장 확인 필요)
1. **"모두 판정 PASS" → "FAIL 0, 확정 수치가 없으면 WARN(확인 필요)"**. 배포 규칙 팩 2026.10.0이 전 항목 미확인이라 PASS가 나올 수 없다. PASS를 만들지 않고 카드·배너에 "확인 필요/미확인"으로 보인다(03장 5장 "확정 수치 없으면 PASS 만들지 않음"과 일치). 확정 팩(테스트의 가짜 팩)에서는 건폐·용적·높이·이격 모두 PASS(테스트).
2. **대화상자 → 3D 보기 아래 인라인 패널**. 이유: 적용 전에 3D 뷰·판정 패널을 같이 보며 목표를 고치기 위해. 같은 컴포넌트를 `Dialog`로 감싸면 대화상자도 된다.
3. **카드의 건폐·용적·높이 값은 judge 레인이 아니라 suggest 응답에 동봉된 `judge()` 결과**. 이유: judge 레인은 "최신만 유효"라 후보 3개를 순차로 보내면 판정 패널의 진행 중 요청이 superseded로 끝나 패널이 로딩에 멈춘다(`judgeReducer`는 superseded를 무시). 값은 같은 엔진 함수(`rules.judge`)가 만든 것이고 화면은 `buildRows`로 그대로 표시만 한다. judge 레인으로 바꾸려면 `useJudgment`의 module seq 공유 + 끝난 뒤 판정 패널 재요청이 필요하다(요청 시 변경).
4. 연면적은 제안 엔진이 낸 **제안 산정값**(`바닥 면적 × 지상 층수`, 0.01㎡ 내림, 지하·발코니·제외 항목 미반영)으로 "연면적(제안 산정)"이라 표시. rules가 면적 분해를 내보내지 않아(036 로그와 같은 이유) 판정 용적률 값과 다를 수 있다.
5. `packages/massing`은 `buildEnvelope`·`judge`(rules)에 의존한다(02_ARCHITECTURE 의존 방향: massing → rules). 문서의 "packages/massing(015·016)" 산출물은 실제로는 `packages/rules`(015 판정, 016 엔벨로프)에 있어 massing은 이번에 처음 채웠다.
6. 탐색 가정: 후보는 축 정렬 직사각형 1개 매스(L자 등 비정형 바닥은 후보 아님). 일조 여유의 "정북 쪽"은 `north_angle_deg`가 가리키는 축(성분 0.2 초과 축을 모두)을 말한다. 최소 한 변 3,000mm·정북 후퇴 2,000mm·정형 모듈 1,000mm·층수 기본 3층·표시 높이 상한 60m는 법규 수치가 아닌 탐색 파라미터(`DEFAULTS`).
7. `max_gfa_m2`는 격자 탐색(후보 8개 × 판정 통과 층수) 안의 최대값이라 "엔벨로프 안에서 이론상 최대"의 하한이다. 문구는 문서 그대로 "엔벨로프 안에서 최대"를 썼다.
8. 매스 제안 결과를 적용하면 id는 항상 `m-1`·`m-1-f<n>`(기존 매스·평면은 교체).
