# AR-06-037 판정 패널 (근거 조항·시행일·팩 버전·대상 여부·폴백 배너)

- 날짜: 2026-10-29 · 근거: 03장 2.7·3.5·5.1절, PRD AR-F-004·007·6.1·9.7, features/README.md, 004b 로그
- 위치: `packages/features/src/judgment/**` (index.ts가 공개 파일, 서브패스 진입점 없음)

## 036이 쓰는 법
```tsx
const j = useJudgment({ model, modelRev, pendingChanges });   // model null이면 요청 안 함
<JudgmentPanel phase={j.phase} data={j.data} errorCode={j.error?.code} onRetry={j.retry}
  hasMass={model.masses.length > 0} massIds={model.masses.map(m => m.id)} onHighlight={ids => ...}
  fallback={fallbackNotice /* 업데이트 만료일 때만 */} onShowRevisions onExtendUpdates revisionCheck={{ lastCheckedAt, today }} />
```
`data`는 엔진 응답 result({result, details, warnings})를 그대로 파싱한 값. 갱신 중에는 직전 데이터가 남고 phase가 loading이다.

## 결정·문서와 다른 점
- **PASS는 만들지 않는다**: 규칙 팩 2026.10.0은 전 규칙 미확인이라 10행이 모두 WARN이다. 근거 칸이 모두 "미확인"이거나 detail.status가 unverified이면 배지 "미확인" + "미확인 — 규칙 팩에 확정된 수치가 없습니다"로 보인다(WARN "확인 필요"와 구분). 측정값(건폐율 30.30% 등)은 참고로 같이 보인다.
- **근거 판정 기준**: `basis`가 빈 배열이거나 법령·조문·시행일이 모두 빈 문자열이면 행을 만들지 않는다. "미확인" 근거는 근거로 인정하되 펼치면 "근거 조문 미확인(법규 원문 대조 전)"으로 정직하게 보인다.
- **예정 규칙(참고) n건**은 지시문에는 pending_changes로 적혀 있으나 pending_changes는 폴백 배너 "이후 개정 n건"(domain 주석)이라, 예정 규칙 수는 엔진 경고 `SCHEDULED_RULES`의 rule_ids 개수로 보인다. pending_changes는 폴백 배너 값 후보로만 쓴다(배너는 props로 받은 FallbackNotice가 정본).
- **폴백 배너는 props 주입**(`FallbackNotice`): EntitlementStatus에 업데이트 기한 필드가 없어서(074·044). 연결은 044가 한다. 오프라인이면 pendingChanges=null → "이후 개정 건수는 온라인에서 확인합니다"(2.7절 단계 2).
- **"개정 확인 필요" 배너(30일)**는 제안 사항: `revisionCheck={lastCheckedAt, today}`가 주어지고 기록 없음·30일 이상이면 표시. `today`는 호출자가 준다(패널은 시계를 읽지 않음). 03장에 확정 문구 없음 — 문구는 이 작업에서 제안.
- 모델러의 `onHighlight(massIds)`: 판정 항목이 매스 id를 갖지 않아(JudgmentResult에 없음) **기하 항목 행**의 "해당 매스 강조" 버튼이 호출 쪽이 준 `massIds` 전체로 부른다. 항목↔매스 대응은 rules가 내보내야 정확해진다(후속).
- 엔진 reason 코드 → 문구 표를 messages.ts에 복제했다(features가 rules를 import하지 않음). rules REASON_MESSAGES에 코드가 늘면 같이 갱신.
- 패널은 packages/ui의 `JudgmentPanel`(데모 목록)을 쓰지 않고 Badge·Banner·Button·JudgmentBadge·EmptyState·Skeleton만 쓴다(행 펼치기·근거 3칸·미확인 상태가 필요).
- 판정 요청 훅은 **실제 엔진 연결 미검증**: 앱에 규칙 팩 공급(load_rule_pack/RulePackProvider)이 아직 없어 워커가 팩을 못 찾는다. 미리보기는 실제 judge 출력 픽스처를 쓴다.
- 테스트 로더: `.tsx`를 Node가 못 읽어 `tsx-hooks.mjs`(apps/web 마케팅 테스트 방식 + 확장자 없는 import 해석, packages/ui용)를 judgment 안에 뒀다.
