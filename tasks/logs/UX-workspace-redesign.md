## A/B 차이
| | A 고정 도킹형 (AutoCAD·Revit식) | B 캔버스 우선 맥락형 (Figma·Rhino식) |
|---|---|---|
| 단계 전환 | 상단 번호 단계 막대 6칸(탭), 단계마다 FAIL 표시 | 상단 가운데 칩(4/6 평면) + 이전/다음 + 펼침 목록, 진행 띠, "도면 만들기 >" 다음 행동 버튼 |
| 왼쪽 | 도구 레일 + 실 목록/시트 목록 패널(상시) | 도구 레일만(분할·병합은 선택 객체 옆 맥락 도구줄) |
| 오른쪽 | 속성·판정·레이어 세로 적층(접기 가능, 셋이 동시에 보임) | 탭 1개(속성/판정/레이어/목록) + 아이콘 띠(접어도 FAIL 수 보임) |
| 판정 | 오른쪽 패널 + 상태줄 | 캔버스 위 떠 있는 HUD(문제 항목만) → 판정 탭 |
| 태블릿·모바일 | 목록은 왼쪽 서랍, 모바일은 패널이 아래 시트, 레일은 아래 도구줄 | 패널은 오른쪽 겹침 서랍, 모바일은 떠 있는 알약 도구줄 |

A 장단점
1. (장) CAD 사용자가 익숙한 배치라 배우는 시간이 짧다.
2. (장) 속성·판정·레이어가 한눈에 보여 수치를 고치면서 판정을 바로 본다.
3. (장) 현재 구현(LayerPanel·PropertyInspector·JudgmentPanel)을 거의 그대로 재배치하면 된다.
4. (단) 1280에서 캔버스가 화면의 약 55%뿐이고, 태블릿에서는 목록을 서랍으로 빼야 한다.
5. (단) 패널이 많아 정보가 빽빽하고, 단계 막대 한 줄이 더 들어가 세로 공간을 쓴다.

B 장단점
1. (장) 캔버스가 넓어(1280에서 약 70%) "도구"처럼 보이는 효과가 가장 크다.
2. (장) 판정 HUD가 문제 항목만 캔버스 위에 띄워 FAIL을 놓치기 어렵다.
3. (장) "다음 단계" 버튼과 진행 띠가 대지 → 제안서 흐름을 이끈다.
4. (단) 속성과 판정을 동시에 보려면 HUD와 탭을 오가야 한다.
5. (단) 맥락 도구줄·HUD·띠는 새 컴포넌트라 구현량이 A보다 많고, 떠 있는 요소가 도면을 가릴 수 있다.

## 도면 편집 층의 결정성 처리 제안
1. 자동 작도 레이어(A-SITE-BNDY·A-SETBACK·A-MASS·A-DIMS 등)는 화면에서 잠금·회색(`--color-concrete`)으로 그리고 편집 도구가 집지 못하게 한다. 사람 주석은 `A-ANNO-USER` 한 레이어에만 쓴다.
2. 주석은 도면 파일이 아니라 `DesignModel.annotations[]`(시트 ID별)에 저장한다. 출력 = `drafting(model, sheetSpec, annotations)` 순수 함수라서 같은 입력 → 같은 바이트가 유지된다. 기존 `annotation_overrides`(치수 위치·문자 끌기)를 이 배열로 합칠지는 팀장 판단.
3. 좌표는 절대 좌표 대신 **모델 객체 앵커**(ref ID + 변/꼭짓점 번호 + 위치 종류) + mm 정수 오프셋으로 저장한다. 치수 값은 사람이 입력하지 않고 엔진이 앵커 사이 거리로 계산한다(문자는 `{값}` 틀만).
4. 출력 순서는 주석 `id` 사전순으로 고정하고, 부동소수는 mm 정수로 반올림한 뒤 쓴다. 문자 서체·크기는 DraftingProfile에서만 정한다.
5. 앵커 객체가 사라지면 "고아 주석"으로 표시(빨간 파선)하고 **출력에서 뺀다**(경고만, 위치 추측 금지). 사람이 앵커를 다시 고르거나 지운다.
6. 골든 테스트: 주석이 없을 때 출력이 지금 골든과 바이트가 같아야 한다. 주석 포함 골든은 새로 추가한다.
