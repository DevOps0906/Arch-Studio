### 방어 없는 항목(남은 위험)
- **감사 행은 DB RPC 안에만 있다**: 서버는 `upsert_drafting_profile`이 쓰는 `core.write_audit`를 믿는다(별도 감사 RPC 없음). 감사에는 바뀐 키 이름만 남고 이전·이후 값은 없다(DB 설계 그대로).
- **로고 sha256 미대조**: 서명 요청의 sha256은 형식만 검사하고, 저장 시 객체 바이트와 비교하지 않는다(서명 기록 저장소 없음). 대신 저장 시 객체 전체를 받아 크기·PNG 구조·허용 청크를 검사한다. CRC·IDAT 압축 해제(실제 디코딩)는 하지 않는다.
- **로고 업로드 객체 정리 없음**: 서명만 받고 저장하지 않은 로고·교체된 이전 로고가 Storage에 남는다(정리 작업 = 후속, `purge_expired` 범위 밖).
- **DXF TEXT의 `%%` 제어 코드**(예: `%%u`): 줄 구조를 깨지 못해 거부하지 않는다(표시만 바뀜). 작성기(021) `textValue`가 제어 문자를 공백으로 바꾼다.
- **레이트 리밋은 인스턴스 메모리**(040과 같은 제약, 운영 전 교체).
- **국외 이전 동의**: HTTP 경로가 없어 화면에서 바꿀 수 없다(미지원 구현). member 우회는 경로 자체가 없어 막힘.
- **캐시 변조**: 같은 PC 사용자가 캐시를 고치면 그 PC에서 만드는 시트 표제란이 바뀐다(검증 범위 안의 값만). 서버·다른 조직에는 영향 없음.

## 2. 결정·이유
- **레이어 규칙 사본 2개(서버·화면)**: apps/web은 domain·drafting, features는 drafting에 의존하지 않는다(package.json·lockfile은 범위 밖). `resolveLayerMap`을 글자 그대로 옮기고 정본을 상대 경로로 불러 생성 사례 400건 + 고정 사례로 세 구현을 대조(정본이 바뀌면 테스트 실패). 의존성 추가 요청: features·web → `@arch-studio/drafting`(그러면 사본 삭제).
- **DB 값 정규식과 resolveLayerMap의 차이**: DB는 `^[A-Za-z0-9_$-]{1,64}$`만 저장(한글·공백 거부, 2400_arch.sql:1633). 03장 와이어프레임 예("대지경계")는 저장 불가. 정본 규칙(DXF 금지 문자 → 표준 유지 + 경고)에 `unsupported_name` 경고를 더해 같은 방식(저장하지 않고 표준 이름)으로 처리했다. 제어 문자·64자 초과·표준 밖 키는 경고가 아니라 422(보안 거부).
- **로고 업로드 경로**: 047 `POST /api/uploads/sign`의 목적 목록(policy.ts)에 로고가 없다(`project_snapshot·render_input·proposal_sheet·consult_audio`). 업로드 서버 코드 수정 금지라 04_API `:59`의 전용 경로 `POST /api/drafting-profile/logo-upload-url`을 같은 규약(서버 경로·upsert=false·사전 크기/확장자·사용 시점 재검사, `tokenExpiry` 재사용)으로 소유 폴더에 뒀다. DB `drafting_profiles_logo_check`·`valid_user_path(org,'drafting-logo',…)`와 같은 경로 모양.
- **미리보기**: features가 drafting을 import할 수 없어 `useEngine()` → drafting 워커 `build_sheet`(sheet 레인, seq) → `svg_preview`를 `<img src=blob:>`로 표시(CSP `img-src blob:` 허용, SVG 안 스크립트 실행 불가). 견본 대지는 골든 `site_plan-basic`과 같은 값. 테스트가 워커 핸들러 결과 = 직접 `writeSvg(buildSheet())` 바이트 동일·2회 동일·고지 포함·체험판은 워터마크일 때만·XML 이스케이프를 확인. 워터마크는 세션 `plan_code === "trial"`일 때(화면 표시용, 출력 판정은 시트 화면·라이선스). 로고는 엔진 표제란에 아직 자리가 없어 미리보기에 없다.
- **로컬 캐시**: localStorage 한 키(`arch.drafting_profile_cache.v1`). 070 어댑터에 설정 저장 포트가 없고 SecureStore는 토큰 전용, Rust `local_settings` 없음 → 셸 prefs.ts와 같은 가장 단순한 방법. 읽을 때 전체 재검증 + 조직 일치, 쓰기는 서버 응답만, 로그아웃 시 삭제. 시트 화면(030)은 `settings/drafting/cache.ts`의 `readDraftingProfileCache(orgId)`만 쓴다.
- **GET 404(not_found)는 "프로필 없음"으로 본다**: 데모 fetch·구버전 서버에 경로가 없을 때 빈 상태로 편집을 보이고 저장은 서버가 판정.
- **오픈소스 고지**: 빌드 시 정적 데이터(`third-party-notices.ts`, 원본과 글자 대조 테스트, `UPDATE_NOTICES=1`로 재생성). 설정 일반 청크 17.15KB(gzip 7.74KB) 중 고지문 약 10.5KB. `@`는 `@`으로 적는다(shell.test 규약 grep이 패키지 이름을 import로 오인).
- **클라이언트 엔타이틀먼트 잠금은 두지 않았다**: 설치형 EntitlementClient가 지금 편집 권리를 전부 `unverified`로 거부해 저장이 항상 잠기기 때문. 서버 402(`entitled`)·DB 권리 검사가 정본.
- 3.15절 치수 단위·자동 저장 간격·저장 위치는 저장 어댑터(`local_settings`)가 없어 만들지 않았다(후속).
