## 결정·이유
- **features는 shell-bridge를 런타임 import하지 않는다**(지시). capabilities는 구조적 `hasCap/byCap`(070 함수와 동치 테스트), 오류는 `{name:"BridgeError",code}` 구조 판별(`bridgeErrorCode`). 규약 테스트(`shell.test.ts`)가 `import type` 외 shell-bridge import를 막는다.
- **데모는 shell-bridge/testing을 쓰지 않는다**: testing은 node:crypto를 쓰고 eslint testDouble이 프로덕션 import를 막는다 → 규칙은 그대로 두고 자체 인메모리 구현(같은 동시성 규칙, crypto.subtle sha256).
- **Mock 패널은 features/src/auth/**에 둔다: boundary.test(Mock 문자열 허용 위치)·eslint authMode 규칙을 고치지 않기 위해. 패널 청크는 `import.meta.env.DEV` 글자 조건 안 동적 import(`dev-panel-loader.ts`), 실제 Mock 모듈은 앱이 넘긴 `loadDevMockAuth`만 연다(이중 잠금). 셸·화면 코드에 인증 단계 변수 이름이 나오지 않는다.
- **finish 재호출**: 앱 재시작 때 저장된 세션이 있으면 `POST /api/auth/finish`를 다시 부른다(008 상태기계에 복구 전이가 없음, 서버 bootstrap 멱등).
- **env 허용 목록**: `VITE_DEMO_MODE` 추가, 릴리스 빌드에 값이 있으면 실패(`VITE_AUTH_MODE=mock`과 같은 방식). env-allowlist.test 케이스 추가.
- **표시 값 보관**: 테마·밀도·GNB 접기는 localStorage(값 검증, 실패 무시). 권한·토큰은 담지 않는다. `local_settings` 어댑터가 생기면 옮긴다.
- **아이콘**: ui Icon에 없는 menu·folder·message·settings·chevron-left·search는 shell/icons.tsx에 같은 규격으로(아래 ui 부족 목록).

## CSP (tauri.conf.json 변경 없음)
- 모듈 워커: 개발 서버(`/src/workers/engine.worker.ts`)·빌드 산출물(`/assets/engine.worker-*.js`) 모두 `worker-src 'self'`로 로드·응답 확인(CSP 위반 0). blob: 불필요.
- **개발 서버 스타일만 문제**: Vite 개발 모드는 CSS를 `<style>`로 주입해 `style-src 'self'`에 막힌다. `'unsafe-inline'` 대신 vite.config.ts에서 서버 시작마다 새 nonce를 만들어 `html.cspNonce` + **개발 헤더의 style-src에만** `'nonce-…'`를 더했다. tauri.conf.json `csp`·`devCsp`는 그대로이고 빌드 산출물은 CSS 파일(link)이라 영향 없음.
- 확인 필요(사람): Windows 외 OS의 `tauri dev`가 devCsp를 HTML에 직접 넣는 경우 개발 스타일이 막힐 수 있다(Windows는 vite 헤더만, 기존 주석). 그때는 Tauri 쪽 nonce 처리(devCsp에 nonce 자리) 판단이 필요 — 이 작업에서는 고치지 않음.
