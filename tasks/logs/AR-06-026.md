# AR-06-026 로그 — 평면 개략도 뷰(floor_plan) + packages/layout

## 구현 요약
- `packages/layout/src/**`(순수 TS, mm 정수, 면적은 ㎡×100 정수 h100)
  - `check.ts` 겹침·외곽 이탈(AR051). 외곽 = `sheet.floor_id` 층과 **같은 level**의 모든 매스 외곽 합집합(`floorOutline`). 경계 접촉 허용·내부 겹침만 위반.
    빠른 경로(상자 → 변 교차 → 표본점 포함) 후 애매한 경우만 `geometry.union` 면적 비교. 변이 가로지르지 않으면 합집합에 새 꼭짓점이 없어 스냅 반올림이 없으므로 면적 비교가 정확하다.
  - `walls.ts` 벽 두께: 실 다각형·층 외곽 = **벽 중심선**(024 "외벽 중심선 가정"과 같은 정의 → 실 면적 = 중심선 면적). 외벽 = 층 외곽 경계 전체, 내벽 = 실 변 중 외곽 경계 밖 부분. 같은 직선의 겹치는 변은 하나로 합침(공유 내벽 1번). 띠 = 조각별 사각형(원래 끝은 두께/2 연장, 개구부 자리는 끊음)의 합집합.
  - `openings.ts` 문·창: `host.edge_index` = 저장된 외곽 고리 순서 그대로의 변, `offset_mm`은 변 시작점부터. 범위 밖(offset<0, width≤0, offset+width>변 길이 — 제곱 bigint 비교)·없는 실/변·같은 벽 직선에서 서로 겹침 → AR051 `opening`. 국소 좌표: x = 벽 따라, y = 호스트 실 안쪽(고리 방향으로 판단).
  - `state.ts` 면적·목표 차이, 편집 상태 `createLayoutState`/`moveBoundary`(바뀐 실만 재계산), `validateLayout`(04_API.md 4.7.5 모양).
  - `solver.ts` Phase 2 솔버 **타입만**(LLM 입력 `LayoutProposalParams`에는 좌표·치수 칸이 없음, 외곽은 엔진이 넣음).
  - `plan.ts` drafting용 묶음 `floorPlanGeometry`.
- `packages/drafting/src/views/floor_plan/**`: `buildFloorPlanView`(위반 시 `FloorPlanError` code AR051), `tryBuildFloorPlanView`(값 결과). A-WALL 띠(pline+ANSI31 해치), A-AREA 실 외곽, A-DOOR·A-GLAZ INSERT + BLOCK 정의, 실명·면적 라벨(값 줄 source_ref `geometry.area.room:<id>`), checks.area_table_m2(`room:<id>`, `rooms_total`).
- 골든 5건: `floor_plan-{single-room, doors-windows, multi-room, skew-wall}`(sheet.json canonical + sha256 + meta), `floor_plan-rejected-overlap`(rejected.json = AR051 목록). 갱신 `node golden/floor_plan-tools/update.ts [--accept]`.

## 문서와 다르게 한 점 / 계약 보충(팀장 확인 필요)
- AR051 `kind`: 04_API.md 4.7.5는 `'overlap' | 'outside'`만. `opening`(문·창 범위 밖·겹침·호스트 없음)과 `invalid`(실 다각형 불량·id 중복)를 더했고, `opening_ids?`·`detail` 필드를 추가.
- 창 레이어는 PRD 9.6절 표준 `A-GLAZ`(작업 지시의 `A-WIND`는 표준에 없음).
- `sheet/errors.ts`는 고치지 않았다: DraftingError는 엔진 불변식용이라 AR051은 `views/floor_plan/errors.ts`의 `FloorPlanError`로 둠.
- 벽 두께: DraftingProfile·DesignModel에 칸이 없어 상수 `DEFAULT_WALLS`(200/100) + `FloorPlanOptions.walls` 인자.
- 목표 대응: `program.targets[].name` = 실 `name` 완전 일치(같은 이름 여럿이면 첫 행). 실 ↔ 목표 연결 키(`target_name`·row id)가 계약에 없다.
- 문 `swing` 정의(계약에 없음): 실 안에서 벽을 볼 때 경첩이 왼손 쪽이면 'left'. 없으면 'left'. 열림 방향은 항상 호스트 실 안쪽.
- INSERT 회전이 90° 배수뿐이라 대각선 벽의 문·창은 방향별로 미리 돌린 블록(`…-D{ux}_{uy}`, rot 0)을 쓰고 문 호는 15° 꺾은선(상수 cos 표).
- 알려진 한계: 직각이 아닌 외벽 모서리 바깥에 작은 홈이 남는다(사각형 연장 방식, 마이터 없음). 개구부와 벽 모서리 간 최소 거리는 검사하지 않는다.
