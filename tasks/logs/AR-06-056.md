## 2. 결정

- [DECISION] (리뷰 🟠 반영) 웹 켜짐 = 스위치 `true` **그리고** 사용 가능한 제공자 있음(워커와 같은 규칙: 지금은 `ARCH_RENDER_PROVIDER=mock` + NODE_ENV development·test). 운영에서 mock·미설정·미지원 값이면 503·차감 0. 같은 입력 표 `RENDER_CONFIG_CASES`로 웹·워커를 각각 검사.
- [운영 조건] fal 제공자 연결 전에는 운영에서 스위치를 켜지 않는다(켜도 503이지만, 웹·워커 제공자 규칙이 어긋나면 차감 후 queued 방치 → 조직당 3건 후 AR030).
- [DECISION] 스위치는 정확히 문자열 `true`만 켬. 웹은 요청마다 `process.env`에서 읽는다(serverEnv 스키마는 소유 밖, 아래 요청).
- [DECISION] 스위치 off 응답 = 503 `ai_render_disabled`, 인증·본문 읽기·DB·Storage 호출 전에 반환(차감 0).
- [DECISION] 동의 없음 = 403 `AI002`(04_API 7장 코드). 오픈소스 렌더 경로가 없으므로 대체 없이 거부(몰래 보내지 않음, SECURITY_BASELINE:294).
- [DECISION] 동의 검사 위치는 quality 검사 뒤·입력 재검사 앞(Storage 읽기 전). 셋 다 차감 전이라 순서 차이로 비용은 없다.
- [DECISION] IHDR 폭·높이 초과 = 413 `AR031`(`details.max_px`). 04_API의 22023(422)은 quality가 상한을 넘는 경우에만 쓴다.
- [DECISION] 객체 없음 = 422 `23514`(경로 오류와 같은 응답, 존재 오라클 최소화), PNG 아님·IHDR 깨짐 = 415, Storage 오류 = 503.
- [DECISION] `quality` high·upscale은 스키마로 받고 22023으로 거부(422 invalid_input과 구분). `inputs.source_render_id` 형식도 22023.
- [DECISION] preset 값 목록이 04_API에 없어 `^[a-z0-9_]{1,32}$` 단어만 받음(목록 확정 시 enum으로).
- [DECISION] 렌더 전용 오류 2개(`ai_render_disabled`·`AI002`)는 `gateway/http.ts`(소유 밖)에 없어 render 모듈 안에서 같은 봉투로 만든다. 로그는 `logger`에 `{ route:"ai_render", code }`만.
- [DECISION] 모의 제공자 선택은 `NODE_ENV`가 명시적으로 development·test일 때만(값 없음도 거부 → 운영 실패 닫힘). 운영에서 제공자가 없으면 핸들러 미등록.
- [DECISION] 워커 재시도: 제공자 호출 전 입력 내려받기 실패만 재시도(`storage`, retryable). 제공자 실패(`AI_UNAVAILABLE`)·출력 검사(`AR032`)·결과 업로드 실패는 재시도 없음(유료 호출 재실행 방지, 실패·환불).
- [DECISION] fal 원가는 `ai_usage`에 기록하지 않는다(모의 구현은 원가 없음, 정산 경로 미정).

## 6. 3단계 — 캡처 PNG·렌더 화면(`/projects/:id/render`)

| 영역 | 파일 | 내용 |
|---|---|---|
| PNG 인코딩 | `packages/features/src/modeler/capture/png.ts` | 캡처 RGBA → 8비트 회색조 PNG(Up 필터, `CompressionStream("deflate")` = zlib, 새 의존성 0, 결정적). 긴 변 1024(표준)·각 10MB 상한, 넘으면 `RenderCaptureError`로 보내지 않음 |
| 모델러 공개 파일 | `packages/features/src/modeler/capture/index.tsx` | `RenderView`(열람 전용 뷰포트 지연 로드, 회전만) + `capture()` → 깊이·윤곽 PNG 2장. render/는 이 파일만 import. 설계 모델·도면은 밖으로 나가지 않음 |

| 화면 | `packages/features/src/render/index.tsx` | 시점(현재 시점 쓰기·윤곽 미리보기·"보내는 것" 안내) / 프리셋·품질(고품질 2K 준비 중 비활성)·CreditCost / 진행(단계·서버 progress)·결과(AI 배지)·실패(환불됨)·만료. 이 PC에 저장·업스케일은 준비 중 비활성. 잡 상태는 `GET /api/jobs/{id}` 2초 폴링(Realtime 전 대체) |

- [DECISION] (리뷰 반영) 실패 표시: 실행 행 `refunded=true`일 때만 "크레딧 N을/를 돌려드렸습니다"(조사는 받침으로). 잡 failed·canceled·오류 코드여도 refunded=false면 "환불 처리 중" + 폴링 계속. succeeded인데 result 없음도 계속 확인.
- [DECISION] 폴링 2초에서 1.5배씩 최대 10초, 전체 4분(서버 3분 초과 환불 + 1분) 넘으면 "진행 상태를 확인하지 못했습니다" + 다시 확인 버튼.
- [DECISION] (리뷰 🟠) 재시도 이중 차감 방지: 같은 캡처·프리셋이면 request_id·업로드 경로를 유지(upsert=false 경로 재사용). 성공 또는 확정 거절(4xx·알려진 비재시도 코드)에서만 버리고, 네트워크·5xx·429·업로드 실패·2xx 응답 해석 실패는 유지.
- [DECISION] `ai_render_disabled`를 api-client 문구 표에 등록(503이어도 자동 재시도 안 함).
- [DECISION] 오류 문구(render 전용, 제안값): `ai_render_disabled`·`AI002`(설정 > 일반 동의 안내, 차감 없음)·`AR030`(5.2절 그대로)·`AR031`(렌더용으로 "다시 캡처하거나 해상도를 낮추세요")·`22023`(준비 중)·`23514`/415(다시 캡처)·업로드 실패·캡처 실패. 그 밖은 api-client 공용 문구.
- [DECISION] preset 선택지는 제안값(재질 5·시간대 3·계절 4, `^[a-z0-9_]{1,32}$` 단어). 3장 6번 결정 후 표만 교체. 자유 문장 입력란 없음(소스 검사 테스트).
- [제약·실패 닫힘] 설치형 CSP(connect-src ipc만, img-src self·data·blob)라 서명 URL 직접 PUT·`<img src=서명URL>`이 막히고, 070 어댑터(`FileGateway`·`PlatformAdapters`)에 업로드·바이너리 받기 경로가 없다 → `localProjects` capability가 있으면 "이 환경에서는 아직 AI 렌더를 지원하지 않습니다"로 요청 버튼 비활성(차감 0). CSP·Rust는 수정하지 않음.
