# AR-06-005 로그 — shell-bridge(NativeBridge·SecureStore·Exporter·LicenseClient·Supabase PKCE) + Rust secrets.rs

## 계획 공격 (착수 전, 2026-10-29)

설계 요지: 화면 → `@arch-studio/shell-bridge`의 `NativeBridge`(팩토리가 Tauri/웹 대체 중 하나를 고름) → `SecureStore` →

## 구현 중 발견 — PKCE verifier 키가 동적(계획 수정)
- 실측(supabase-js 2.118.0): 로그인 시도마다 `auth.session-flow-<32hex>-code-verifier`를 새로 만들고, 목록 `auth.session-flows-code-verifier`,
  구 키 `auth.session-code-verifier`도 쓴다. 로그아웃 때 `auth.session-user`도 지운다. 정확 일치 허용 목록 `auth.session-code-verifier`는 깨진다.
- 키체인은 항목 열거가 안 돼 동적 키를 그대로 저장하면 로그아웃 시 다 지운다고 보장할 수 없다(#6 위반).
- 해결: TS 어댑터(`supabase/client.ts`)가 PKCE 키 3종(정규식 검사)을 키체인 **한 항목 `auth.pkce`** 의 JSON 필드로 모은다. 시도별 verifier는
  최대 8개(오래된 것부터 버림), 읽기-수정-쓰기는 어댑터 대기열로 직렬화, 손상된 JSON은 빈 묶음. `auth.session-user`는 저장 안 함(읽기 null·지우기 무시·쓰기 거부).
  Rust 허용 목록은 고정 2개 `auth.session`·`auth.pkce`로 유지.

## [DECISION] 키체인 값 크기 — 분할 저장 (2026-10-29, 작업자 판단)
- 선택지: (a) 분할 저장, (b) refresh token만 저장하고 나머지는 재시작 때 갱신으로 복원.
- (b)는 supabase-js가 저장소에서 읽은 객체를 그대로 세션으로 쓰므로 가짜(access 없는) 세션을 만들어야 하고, 라이브러리 내부 검증 규칙에 기대는 우회라 버전 올림마다 깨질 수 있다. 오프라인 시작 때도 세션 정보가 사라진다.
- (a) 채택: Rust `SecretStore`가 한 키를 `<키>#0..#n` 조각 + 헤더 `<키>`(`v1:<조각 수>:<SHA-256>`)로 저장. 헤더를 마지막에 쓰고 읽을 때 해시 검증 → 중간 실패는 "없음"(실패 닫힘, 재로그인). 조각 크기 2,000바이트(Windows 2,560바이트 한계 아래), 값 상한 16KiB.

## 위협 모델 명시
- **XSS = 토큰 탈취.** 같은 출처에서 스크립트가 실행되면 웹뷰·웹 모두 메모리의 세션과 키체인 명령(`secret_get`)을 읽을 수 있다. 키체인·메모리 저장은 이를 막지 못하며 **CSP가 유일한 방어선**이다(CSP 강화는 별도 작업의 몫).

## 독립 보안 리뷰 지적 수정 (2026-10-29)
- `createArchSupabaseClient`가 입력을 검증한다: `sb_secret_` 키, payload `role === "service_role"` JWT, https가 아닌 URL(`http://127.0.0.1`·`http://localhost` 개발 예외)을 `BridgeError`(`SUPABASE_KEY_FORBIDDEN`·`SUPABASE_URL_INSECURE`)로 거부. 메시지에 키·URL 값 없음.
- 테스트 더블(`@arch-studio/shell-bridge/testing`·`testing/`·`test-helpers`)은 `eslint.config.mjs`의 영역별 계산 구조(`restrict`/`area`)에 `testDouble` 묶음으로 통합: 정적 import와 동적 `import()` 모두 차단, `*.test.ts(x)`에서만 허용.
- Rust 통합 테스트(`capabilities.rs`·`ipc_commands.rs`)의 로컬 출처를 플랫폼별로 선택(Linux에서 통과). `build.rs` `APP_COMMANDS` = `generate_handler!` = capability `allow-*` 집합 일치 테스트 추가.

## 리뷰 후속 (미구현, 위험으로 기록)
- **웹 BroadcastChannel 토큰 전송(#8)**: 완화 후보 (1) 072 httpOnly 쿠키 본 구현에서 클라이언트 세션 저장 자체를 대체, (2) 웹용 클라이언트 생성 시 `BroadcastChannel` 차단(생성 구간에서만 전역을 치환하는 방식 검토), (3) supabase-js 버전을 고정하고 "세션 토큰이 BroadcastChannel로 나가지 않는다" 회귀 테스트를 둔다(버전 올림 때 깨짐을 감지). 설치형(Tauri)은 같은 출처 탭 개념이 없어 영향이 작지만 동일 검사를 권장.
- **단일 인스턴스 보장 없음**: Rust `Mutex`와 TS 대기열은 프로세스·객체 단위라 앱을 두 번 띄우면 같은 키체인 항목에 대한 읽기-수정-쓰기가 겹칠 수 있다. 008 후속으로 `tauri-plugin-single-instance` 도입(새 의존성이라 `secscan license` 확인 필요, 새 capability/플러그인 = 위험도 높음 리뷰).
