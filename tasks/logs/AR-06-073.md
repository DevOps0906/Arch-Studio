# AR-06-073 클라우드 프로젝트 blob 저장·RLS·expected_version 충돌

## [DECISION] 착수 전 (2026-11-02, 팀장 + 사용자) — challenger REVISE 반영
1. 001 스키마 소유 예외 승인(팀장). 정본은 새 조각 `supabase/modular/2402_*.sql` + 새 타임스탬프 마이그레이션, `scripts/db/convert.mjs` TARGETS에 추가(골든 검사). 2400·2401·적용된 마이그레이션 수정 0.
2. save RPC는 **service_role 전용**(start_ai_run 선례). authenticated EXECUTE 회수. 옛 4인자 `save_cloud_project(uuid,text,text,integer)`는 같은 마이그레이션에서 drop(오버로드 모호 PGRST203 방지). 인자 순서는 default 없는 인자 먼저. route가 세션·web_edit·레이트리밋·업로드 객체 재검사(존재·크기) 후 호출.
3. 업로드 폴더 키 = `project_uuid` 하나로 통일(05_DATA_MODEL 189). CHECK·service.ts:176-177·upload-url 서명 폴더를 모두 맞춘다. 기존 행은 project_uuid 백필(로컬 데이터만, 운영 데이터 없음).
4. 유일성 `unique(org_id, project_uuid)`(전역 PK 아님, 존재 오라클 방지). 기존 `id` PK·감사 로그 유지. 다른 조직 uuid는 P0002 은닉.
5. local_id: 같은 org에서 같은 local_id·다른 project_uuid → 23505를 명시 코드로 매핑(409, 500 금지). project_uuid 불변을 트리거로 강제. local_id null→값 설정은 허용.
6. 조회 RLS = 조직 멤버십만(has_entitlement 제거) → entitled=false도 목록·열람 허용(04_API 60·62). 쓰기는 RPC만. 보존 상태 테이블(cloud_retention)은 만들지 않음(후속).
7. 원자성: 조직 advisory lock + FOR UPDATE 유지. `version = expected`가 아니면 AR041, 상한 초과 AR040. 동시 요청 테스트(시나리오 9) 필수.
8. 오류 수치(현재 버전·상한)는 메시지 문자열이 아니라 DETAIL(JSON)로 넘기고 route가 구조화해 응답(원문 노출 0).
9. **삭제 포함(사용자 결정)**: `DELETE /api/cloud-projects/{id}` + service_role 전용 삭제 RPC(조직 확인·감사 로그·expected_version 선택). Storage 객체 정리는 같은 요청에서 시도, 실패는 고아 목록으로 남기고 로그(본문 0).
10. bytes·schema_version은 서버가 업로드 객체 메타로 검사(클라이언트 값 신뢰 0). blob 상한은 버킷 100MB, 조직 총용량은 `미확정`(Q4). 옛 blob·AR041 실패 업로드 고아 정리는 후속(크론) — 기록만.
11. 범위: 저장·목록·사용량·충돌·삭제. `GET …/blob` 열기는 072 몫. `supabase/tests/rls_smoke.sql` 옛 시그니처 갱신 + 다른 조직 0건 케이스 추가.
