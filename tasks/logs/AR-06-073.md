# AR-06-073 클라우드 프로젝트 blob 저장·RLS·expected_version 충돌

## [DECISION] 2026-11-02 착수 전 challenger(REVISE) 반영 — 팀장·사용자 결정
1. 새 테이블이 아니라 기존 `cloud_projects`(20261013000002_arch_domain.sql:206-221)를 새 번호 마이그레이션으로 ALTER. `id` PK 유지(write_audit 호환), `project_uuid uuid` 추가 + `unique(org_id, project_uuid)`, `local_id` nullable. modular 쌍 `supabase/modular/2402_*.sql` 추가. 표식 관례(`/*@schema*/`) 따름.
2. 백필(사용자 결정): local_id가 UUID 형식이면 그대로, 아니면 새 UUID 발급. 이후 NOT NULL.
3. 폴더 키는 항상 project_uuid. 경로 CHECK·local_id 변경 금지 트리거를 교체하고 `apps/web/src/server/cloud-projects/service.ts` snapshotFolder도 project_uuid로 통일.
4. RLS SELECT: 조직 구성원이면 entitlement 없이 목록·읽기 허용(04_API:60·62, ADR 3.3·D-H5). 쓰기는 기존 권리 검사 유지. 스모크에 "만료 조직 읽기 가능"·"다른 조직 0건" 추가.
5. RPC 교체: 옛 `save_cloud_project(uuid,text,text,integer)` DROP, 새 함수 revoke public/anon 후 authenticated만 grant. RPC 안에서 `storage.objects`(bucket arch-user) 존재·크기(≤100MB) 재검사, 목록 bytes는 이 값 사용. web_edit 재검사는 074 몫(공백 기간 수용, 로그에 명시).
6. 이전 버전 보존(사용자 결정): 최신 1개만 유지. 저장 성공 후 이전 객체 삭제(실패해도 저장은 성공, 로그만). 거절·중단된 업로드 고아는 정리 크론 후속(작업 표 '발견한 문제'에 등록).
7. AR041은 현재 버전을 메시지 원문이 아닌 detail/hint로 전달, 23505(같은 local_id·다른 uuid) → 409 매핑.
8. 사본 저장: 새 엔드포인트 없음(새 UUIDv7 → upload-url → POST expected_version 0). blob GET(열기)은 072 소유 — 이번 범위 밖.
9. 상한: 객체 100MB, 조직 건수 cloud_projects_max(체험 3·유료 100), 바이트 총량은 Q4 전 미구현.
10. 검증 추가: sql2erd로 docs/diagrams/erd.mmd 갱신, 타입 재생성, pnpm test:rls(db reset 먼저), node scripts/db/check.mjs.
